# paper-plans

論文の企画案（plan）を置く。ここで育て、**書くと決めたものだけ** `outputs/papers/` へ昇格させる。

- 企画段階 = `paper-plans/`（1ファイル = 1企画、`NNN_<topic>.md`）
- 執筆段階 = `papers/`（1ディレクトリ = 1論文、構成は `outputs/papers/README.md`）

---

## 昇格の判断基準（paper-plans → papers）

昇格は「この企画を論文として書き切る」という**執筆コストの投下宣言**であり、途中で撤回すると `papers/` に未完の骸が残る。したがって **G1–G6 がすべて `達成` のときにのみ昇格を提案する**。`達成` 以外の判定（`未達` / `評価不能`）が1つでもあれば据え置き、その項目を当該 plan の「昇格判断」節に書く。

判断の土台は `inputs/seeds/lambda-statement-program.md` の選別基準 (i)–(iv)、`docs/themes.md` の3トラック、`docs/schemas.md` の StatementCandidate、および `MEMORY.md` の各サイクル総括。

**記入先の固定**: G1–G6 の充足状況は、当該 plan の末尾の「## 昇格判断」節に**表形式で**書く。判定語は `達成` / `未達` / `評価不能` / `非該当` の4つだけを使う。`非該当` は、G6 の4項目のように**企画の性質上その論点が発生しない**場合にのみ使う（ゲート全体を `非該当` で飛ばすことはできない）。

**G1 は他ゲートの前提**: 中核命題が命題文として存在しない間（G1 未達）、G2・G4・G6 を `達成` と判定してはならない。ただし、**必要な記載そのものが欠けている**こと（例: `resolved_risk` / `novelty_risk` が一言も無い、G6 の4項目の該当/非該当が未記載）は中核命題に依らず確認できるので `未達` と判定する。記載はあるが中核命題が未確定ゆえに評価できない場合のみ `評価不能` とする。要求項目が複数あるゲートでは、**1項目でも記載が欠けていれば `未達`**。全項目に記載があり、中核命題が未確定ゆえに妥当性・網羅性を確認できない場合にだけ `評価不能` を使う。

### G1. 中核命題が厳密に書き下されている

- 論文のテーゼを担う**中核命題（主定理・主予想・分離定理）が、仮定・結論・成立する一般性の範囲まで確定した命題文**として plan 内に存在する。
- 「観察」「示唆」「〜と思われる」の段階は `未達`。**どの一般性で成立するかを書けない命題は昇格させない。**
- 中核命題の**一般性の範囲を確定するために必要な計算が完了**していること。plan が過去に「これが要る」と挙げた計算を**削除して通すことを禁じる**。不要と判断して外す場合は、その理由を「昇格判断」節に書く。

### G2. 帰属と ℝ脱出が明示されている（選別基準 (i)(ii)）

- **中核命題が扱う各量**について、$\mathbb{N}$ / $\mathbb{Z}[x]$ / $\Lambda$ / $\overline{\mathbb{Q}}$ のどこに住むかの台帳が **plan 内に**書かれている。共通 seed の台帳を指すだけでは不足（この企画の量について書く）。
- $\mathbb{R}$ を使う箇所が**一点に隔離**され、その一点が明示されている（または有限 $N$ 命題として $\mathbb{R}$ を一切使わない）。
- seed が「進まない」とする **$\overline{\mathbb{Q}}(\ell_p)$ の非線形部（Schanuel 条件付き層）** を本体に含まない。

### G3. 検証計算が実行済みで再現可能

選別基準 (iii) は「SageMath で厳密計算でき、**原理的に** Lean/Coq の decide・witness に乗る」を要求する。昇格ゲートでは **SageMath 側だけこれを強化**し、Lean 側は原理的可能性で足りるとする。

- **SageMath（必須）**: 中核命題を支える計算が `sagemath/check/<dir>/` にあり、
  - 対象・手順・結論を書いた `README.md` と、
  - 実行ログ（`.out`）
  が存在する（本プロジェクトの実運用規約。`overview.md` 形式は Ising プロジェクト側の規約であり、ここでは要求しない）。
  - 「原理的に検証可能」だけでは `未達`。**実行ログのない主張は昇格根拠にできない。**
- **Lean（条件付き）**: plan が Lean 成果物を含めると宣言した場合にのみ適用し、`lake build` と no-sorry 検査が緑であることを要求する。宣言しないなら **plan から Lean 関連の記述をすべて外すこと**（計画に残したまま「非該当」で通す抜け道を禁じる）。本プロジェクトには現在 `lean/` が無いため、宣言する企画は環境導入から行う。

### G4. 既知性リスクが調査済み（`resolved_risk` / `novelty_risk`）

- **既に解決済みであるリスク**（`resolved_risk`）と**既知定理から自明に出るリスク**（`novelty_risk`）の双方について、調査した範囲・結果・**根拠文献名**が plan に書かれている。未記載なら `未達`。
- 中核命題の**先行研究アンカーが文献名で特定**されている。
- 選別基準 (iv) に従い、**アンカーから動かした軸を列挙し、それが 1 本であること**を示す。軸は対象軸（境界・rank・模型・複雑性・可解性）とメタ軸（可算化・決定可能性・形式検証可能性）の6本。2本以上動いているなら分割するか、複合である理由を書く。T1 Reframe はメタ軸のみを動かすトラックなので、**対象軸を1本も動かしていないこと**（数学的内容は既知のまま）を明示する。
- 対応する `outputs/candidates/` の候補があるなら、その `paper_potential` を引く。`low` の場合は、plan 側でその評価をどう覆したかを書く。**`high` は要求しない**（本リポジトリの既存候補はすべて medium 以下で、`high` は1件も無い。`high` を条件にすると誰も昇格できない）。なお既存候補には `low-medium` / `unknown` という `docs/schemas.md` の値域（high/medium/low）外の値が使われている。見つけたら値域内へ是正する。

### G5. トラックに応じた寄与が、確認可能な形で示されている

`docs/themes.md` の3トラックで要求が異なる。**どのトラックの成果として書くかを plan に明記**し、対応する成果物を提示する（免責文を1行置くだけでは `未達`）。

| トラック | 提示すべき成果物 | 誇張の禁止 |
|---|---|---|
| T1 Reframe | 厳密化の**対象となった既知結果を文献名で特定**し、厳密化によって新たに機械検証可能になった命題を**列挙**する（再框自体が first-class 成果） | 「可積分の新定理」と呼ばない。再框であることを明示する |
| T2 Solve | **新しい厳密解または明確な部分前進**を提示し、既存結果の再導出でないことを文献照合で示す | 有限 $N$ の帰属・計算可能性（四軸 1・2）は極限の可解性（四軸 4）を何も含意しない。混同しない |
| T3 Pure | 純粋数学側の**未解決問題に対する厳密命題または部分結果**を提示する | 数値実験の一致を証明と呼ばない |

### G6. 統計的・論理的な健全性チェックを通過している

過去サイクルで実際に起きた誤りの再発防止。**4項目それぞれに `該当（対処内容）` / `非該当` を書く**（無言の省略は `未達`）。

1. **0件を仮説の支持根拠にしない**。cycle 5 で六頂点 Wall の 0/43 を「有意でない」と判定し、cycle 6 で標本を 572 件へ桁で拡大したところ **4.5% の反例が出て仮説を棄却**した。0件を根拠にするなら、帰無仮説・使用した検定・p 値・必要標本数を明記し、**標本を桁で拡大した結果**を添える。
2. **構造判定を代理指標で行わない**。カイラル Potts の Onsager 構造判定で、cycle 4 は「全2冪次数・全実・少数√」の観察（いずれも代理指標）を根拠に**肯定**、cycle 5 は「N=4,5 で非2冪因子」（代理指標）と「一般 λ は超可積分点でない」（代理指標ではない）の二点で**撤回**、cycle 6 が**超可積分点について** **Dolan–Grady 関係式**で Onsager を確定し、代理指標に依った部分が過剰訂正だったと判定した。代理指標（次数・桁）は肯定にも否定にも誤用された。**Onsager 構造なら Dolan–Grady 関係式で判定する**など、定義に直結する判定手段を名指しで使う。
3. **スケールの偶然一致を接続と呼ばない**（cycle 10 の 4G/π と Lehmer 数はスケール違いの偶然）。
4. **数値一致は証拠であって証明ではない**ことが、plan の記述で区別されている。

## 昇格の最終ゲート（ユーザー判断）

G1–G6 は**必要条件であって十分条件ではない**。「どのテーマを論文として世に出すか」はユーザー固有の価値判断であり、自動ループやエージェントが単独で決めてよい事項ではない。

- 根拠: `MEMORY.md` の cycle 1 総括「cycle 2 方向はユーザー判断待ち（基礎論寄与に価値を置くか／カイラル Potts 直撃／D-U2 数論定理化／撤退）」および cycle 2 総括の同旨。企画の価値づけが繰り返しユーザー判断に差し戻されている。
- G1–G6 をすべて満たした時点で、**エージェントは昇格を提案するところまで**を行う。
- 実際に `papers/` へ移すのは**ユーザーの承認後**。承認は、承認日と承認範囲を当該 plan の冒頭に追記して記録する。

## plan の状態語彙

`据え置き`（`達成` 以外のゲートあり） / `昇格提案済`（G1–G6 充足、ユーザー承認待ち） / `昇格済` / `破棄`。

## 昇格手順

1. 該当 plan の「昇格判断」節に G1–G6 の充足状況を、根拠（コミット・検証ログのパス・文献名）付きの表で記す。
2. ユーザーへ提案し、承認を得る。承認日・範囲を plan 冒頭に記す。
3. `outputs/papers/NNN_<topic>/` を `outputs/papers/README.md` の標準構成で作成する。
4. plan 本体は `paper-plans/` に残し、冒頭に昇格先へのリンクと状態 `昇格済` を追記する（企画の履歴を消さない）。
5. 検証コードの実体は `sagemath/check/` に置いたままとし、`papers/NNN_<topic>/computations/` にはそこへの参照（パスと実行手順）を置く。
6. 該当プロジェクトの `MEMORY.md` を更新し、main へ push する。

## 昇格後にゲートが崩れた場合

昇格後に検証が落ちた・反例が出た・先行研究が見つかった場合は、`papers/` の当該論文の `notes.md` に事実を記録し、中核命題が維持できないなら plan の状態を `据え置き` へ差し戻す。**崩れたゲートを黙って通したままにしない。**
