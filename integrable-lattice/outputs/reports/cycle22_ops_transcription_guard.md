## 2. 設計 — 3 件の実例から何が機械検出できるかを決めた

「対応表があるかどうか」を見る道具にしてはならない。**過去 3 件はいずれも対応が付いていた**うえで
中身が落ちている。そこで 3 件を並べて、**何が落ちたのか**の形を見た。

| 事故 | 根拠 report が持っていたもの | 本文に起きたこと | 形 |
|---|---|---|---|
| cycle 18 | 「Skolem–Mahler–Lech 例外（**算術級数の有限和**）」 | 「**有限個の** $N$ で例外」 | report の**語**が本文に無い |
| cycle 20 | 「最後の等号は 補題 A2 (1)（$A_1\equiv0$）から**従う**」 | この仮定が本文に無い | report の**記号**が本文に無い |
| cycle 21 | 係数は指数ごとの族 $\mu_\gamma$（桁 $c$ の枝では $\mu_{c+\ell\gamma}$） | $\sum_{\gamma\in\mathcal{G}_c}\mu\,(1+y)^{\gamma}$ | **添字が落ちた** |

前 2 件は「report にあるものが本文に無い」、3 件目は「本文の中だけで閉じた不整合」である。
形が違うので**別々の検査**にした。

### 2.1 検査 A（台帳あり）: 根拠 report からの取りこぼし

`tools/source-links.ts` が **本文ブロック → 根拠 report の範囲**を持つ。範囲は行の目印
（`from` / `to`）で指し、**目印が消えていれば検査は例外で落ちる**（台帳が腐ったまま緑にならない）。

検査するのは、その範囲のうち**条件・例外・仮定を述べている文**に現れる

- **飾りつきの数式アトム**（$\mu_\gamma$ と $\mu_{c+\ell\gamma}$ と $\mu$ を別物として区別する）
- **専門語**（漢字・カタカナの連なり。汎用語は落とす）

が、本文ブロックにも現れることである。

**なぜ「条件文」に絞ったか（実測に基づく）**: 範囲の全文を照合対象にすると、
3 ブロックだけで未確認 47 件になり、その大半は証明の途中式と report 内部の履歴だった。
探しているのは「**条件**が落ちる」型なので、`ただし` `例外` `仮定` `から従う` `反例` `ときに限る`
などの目印を含む文だけを見る形にした。過去 3 件の該当箇所はいずれもこの目印を持つ。
1 行に収まらない文があるので（cycle 20 の $A_1\equiv0$ は「から従う」が次の行にあった）、
地続きの行を連結してから文へ切っている。

**免除は項目 1 つ単位でしか書けない。** ブロックを丸ごと免除する形は作っていない
（それが cycle 21 で実際に穴になった形だからである）。免除には
「なぜ本文の主張が、その記号・語を落としても成り立つのか」を書く。

### 2.2 検査 B（台帳なし・全ブロック）: 添字族の裸使用

cycle 21 の事故は report との照合では捕まらない。実際に確かめた——
本文の $g_c(y)=\sum_{\gamma\in\mathcal{G}_c}\mu_{c+\ell\gamma}(1+y)^{\gamma}$ という式は
report に逐語では存在せず（report は測度 $\nu_c$ の言葉で書いている）、
裸の $\mu$ は report の §2.1 にも現れる（$\mathcal{G}(1,3)=\{1,3,5,7\},\ \mu\equiv1$）。
**アトムの照合では検出できない。**

そこで**本文の中だけで閉じた規則**にした:

> 記号 $S$ が同じブロック内で「束縛変数 $v$ を含む添字つき」で使われているとき、
> $v$ を束縛する $\sum$ / $\prod$ の**被和の中に裸の $S$** があれば違反。

事故当時の式はこれに当たる（同じブロックが 2 つ前の displayMath で
$\mu_\gamma=\sum_{pa+qb=\gamma}\bar c_{pq}$ と族を定義しているのに、
$\gamma$ で束縛された和の中で $\mu$ を裸で使っていた）。

台帳を要さないので**全 43 ブロック・数式 1343 件**に走る。
偽陽性は現在 0 件（設計中に 1 件出たが、原因は束縛変数の取り方だった。§6.2）。

## 3. 例外表の穴を塞いだ（日英対応検証）

### 3.1 穴の正体

旧 `ja-en-exceptions.ts` は「ブロック id → 理由の文字列」で、
**登録するとそのブロックの数式照合が丸ごと免除された**。

### 3.2 直し方 — 免除の単位を「差分 1 つ」へ落とす

登録は `{ reason, allow }` になった。`allow` は**どの種類の差なら出てよいか**を宣言する規則の列で、
`tools/ja-en-diff-rules.ts` が持つ:

| 規則 | 何を許すか | 何を許さないか |
|---|---|---|
| `text-body-translated` | `\text{}` の**中身だけ**が英訳されている | 中身を伏せて 1 文字でも違えば不可 |
| `text-body-translated-reordered` | 上に加え、`\text{}` の前後の記号の**順序**が英語の語順へ変わっている | `\text{}` を除いた残りの**多重集合**が一致しないと不可（記号の増減は不可） |
| `repo-internal-texttt-removed` | `\texttt{...}` **だけ**からなるノードを投稿稿から落とした | `\texttt{}` だけのノード以外には当たらない |

差分を規則で 1 つずつ説明し、**説明できない差が 1 つでも残れば違反**になる。
宣言した規則が 1 度も使われなければ「登録が古い」として報告する（実際に 1 件見つかって消した）。

## 5. 本文へ回す 2 件（この step は本文を触らない）

### 5.1 【要修正】命題 K の英語版で $\ell$ が落ち、"p-adic" になっている

- 場所: `structured-latex-en/content/009_s_infinity_decision.ts`（命題 K の (K4) の直後）
- 日本語正本: 「… (J4) の $j^*$（**$\ell$ 進近傍**の変形から定まる量）は …」
- 英語版: `" — a quantity read off from a deformation in a p-adic neighbourhood — "`
- **問題は 2 つある。**
  1. インライン数式ノード `\ell` が落ちている（cycle 21 の 11 個と**同じ型**の脱落）。
  2. **この論文で $p$ は別の素数を指す**（命題 N・命題 C′ の $p$）。塔の素数は $\ell$ である。
     したがって "p-adic" は記号の取り違えであり、記述の不備ではなく誤りである。
- 直し方: `"a quantity read off from a deformation in an "`, `math(\`\\ell\`)`, `"-adic neighbourhood"`
  のように $\ell$ を数式ノードとして戻す（日本語版は正本なので変更しない）。
- **この 1 件のため、現在 `structured-latex-en` の `npm run check:full` は違反 1 件で落ちる。**
  規則に登録して免除することもできたが、**それは訳し落としを例外表で隠す操作**であり、
  この step が塞ごうとしている穴そのものなので**しなかった**。
  本文を直せば緑になる。`npm run check`（英語版）は通る。

### 5.2 【要判断】命題 K に $e_{m_u}$ の明示式が無い

- report（`cycle20_T3_s_infinity_decision.md` 定理 W4）は $e_{m_u}=\mathrm{ord}_{x=0}\bar\psi_u(G)$
  （$G=\bar{\tilde E}/(\chi^v-1)^{m_u}$）という**値の式**を持つが、本文には無い。
- 本文の主張は成り立つ。(K4) が言うのは $j^*(P)=m_u$ であり、(K5) が $e_{m_u}$ を $r_0$ の式に
  含むものの、そこで要るのは $e_{m_u}<\infty$（(K4) が述べている）だけである。
- ただし **$r_0$ を実際に計算するには $e_{m_u}$ の値が要る**ので、
  「$D$ の係数からの有限計算で決まる」という (K3)・(K6) の主張との整合を読者が辿れるようにするなら、
  明示式か report 参照を置く価値がある。**書くかどうかは本文の担当が決める。**
  検査は台帳の免除としてこの事実を記録してある（`source-links.ts` の `\psi_{u}` の項）。

## 6. この道具が捕まえられないもの（限界。先に書く）

1. **場合分けの条件の意味の誤り。** cycle 21 の 命題 G″ で「$\lambda_1$ が定義されない場合を含む
   条件」（`(\text{B}:\ \lambda_1\ge2,\ \text{および全ての場合の } n=1)`）になっていた件は、
   記号としてはすべて正しく現れるので検査 A も B も挙げない。**あれは Lean 化が見つけたものである。**
   転記検査は Lean 化の代わりにならない。
   （なお日英の両方が同時に壊れていなければ、`text-body-translated-reordered` の多重集合照合が
   拾う形ではある。実際に当時は日英とも同じ形で壊れていたので拾えない。）
2. **report が書いていない誤りは原理的に見つからない。** report 自体の誤りも見つからない。
   この道具は「report が正しい」を前提にしている。3 件ともその前提は満たしていた。
3. **台帳に載っていないブロックは検査 A の対象外**（現在 32 ブロック中 24 が対象外）。
   ツールは毎回この件数を出力する（黙って落とさない）。
4. **語の切り出しは形態素解析ではない**（漢字・カタカナの連なりを語とみなす粗い切り方）。
   したがって「この語が本文に出てこない」は**疑いの根拠であって、誤りの証明ではない**。
   免除の理由を書く作業がその判定を担う。
5. **検査 B は族の定義が同じブロックに無いと当たらない。** 別のブロックで定義された族を
   添字なしで使っている場合は検出できない。また被和の範囲は構文解析ではなく粗い近似
   （束縛子の直後から `,` / `\qquad` / `\\` まで）なので、**範囲を狭く取る側に倒してある**——
   見落とし（偽陰性）は起きるが、無関係な部分を巻き込む偽陽性は起きにくい。
6. **日英の規則は「記号の多重集合」までしか見ない。** `text-body-translated-reordered` は
   並べ替えを許すので、記号の**順序を変えて意味を変える**書き換えは通る。
   増減は通らない（それが 11 個脱落の型である）。

## 10. 自分が犯した誤り（隠さず記録する）

### 10.1 最初の検査 A は「report の全文と本文を照合する」設計で、使い物にならなかった

3 ブロックだけで未確認 47 件が出た。内訳を見ると、$\blacksquare$・$\mapsto$ のような組版の記号と、
「理由」「変化」のような汎用語と、証明の途中で使うだけの補題の記号だった。
**「厳しくすれば安全」ではない。** 免除の登録が中身の無い作業になり、
そのうち誰も内訳を読まなくなる（それは cycle 21 の例外表がたどった道と同じである）。
探している事故の形（**条件が落ちる**）に絞って初めて意味のある検査になった。

### 10.2 検査 B の束縛変数の取り方を間違えて、偽陽性を 1 件出した

最初は $\sum$ / $\prod$ の添字に現れる記号を**すべて**束縛変数として扱った。
その結果 `\prod_{z_i^L=1}z_i^{a}` で「$L$ が束縛変数、$a_L$ が族、$a$ が裸」と読み、
`paper_021_definition_curve` を挙げてしまった。$L$ は走る変数ではなく固定された段数である。
`\in` / `=` の**左辺**だけを見て、さらに**肩に乗っている記号を外す**ようにして消えた。

### 10.3 再現データの期待値を、正規化後の形ではなく元の形で書いた

cycle 20 の再現で `A_1` を期待値に書いたが、アトムは飾りを `_{...}` へ畳むので `A_{1}` になる。
テストが「検出できない」と言うので実装を疑ったが、**実装ではなく期待値の書き方が間違っていた**。
検査そのものは最初から $A_1$ を挙げていた。

### 10.4 例外表の穴を塞いだ結果、既存の検査が赤になった

`verify:correspondence` は §5.1 の 1 件で落ちるようになった。
これは**新しい検査が本物の不備を見つけた**結果であって、道具の後退ではない。
規則に登録すれば緑にできたが、それは訳し落としを例外表で隠す操作であり、
この step が塞ごうとしている穴そのものなので**しなかった**。
本文を直す権限がこの step に無いため、**赤のまま残して §5.1 に直し方を書いた**。
