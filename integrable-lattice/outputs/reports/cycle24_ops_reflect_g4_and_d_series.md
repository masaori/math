## 2. cycle 24 step 1 の訂正が、どう反映されているか

**3 件とも訂正後の形で入っている。訂正前の形は本文に 1 つも残っていない。**

### 2.1 定理 D2 の最後の一文（初稿は偽だった）

初稿は「$T_\mathrm{def}=0$ と、閉形式が $n\ge0$ から成り立つことは同値」だった。
$\Rightarrow$ 方向が偽である（総和が $0$ でも部分和が $0$ とは限らない）。

本文 (U2) は**訂正後の 3 分岐**で書いた。$\delta_M:=\Theta_M-\Theta^\mathrm{as}_M$、$S(n):=\sum_{M\le n}\delta_M$ を導入し、

1. レベル $n$ で閉形式が成り立つ $\iff S(n)=T_\mathrm{def}$、
2. $T_\mathrm{def}=0\iff$ **$n=0$ で**成り立つ、
3. **全ての $n\ge0$ で**成り立つ $\iff \delta_M=0$（全 $M$）であり、これは $T_\mathrm{def}=0$ より**真に強い**、

の 3 つを列挙し、そのうえで 3 番目の逆が言えないことと、原本と同じ反例
（$\Theta_1=1,\Theta_2=-1$）を置いた。**原本が付けた反例の射程の限定**
（「実在の塔で $\delta_M$ の符号が混ざる例は確認していない」）も落とさずに入れている。

### 2.2 定理 D3・D5 の $\min$ の規約

$\min$ を $A_m\ne0$ の $m$ に限る規約（$v_\ell(0)=+\infty$）を、本文の **3 か所**に書いた。

- **(M1)**: 規約の本体。**なぜ書き落とせないかまで書いた**——
  $v_\ell(0)=0$ と読む流儀（計算機代数系と形式化ライブラリの既定）で読むと、(U4) の主役である
  $p=1$ の塔で $\Lambda_1$ が $2$ ではなく $0$ になり $c$ が変わって結論が壊れる。
- **(U4)**: 定理 D3 の側。$A_0=A_1=4$、$A_2=1-p$ を明示し、$p=1$ で $A_2=0$ になることを本文に書いた。
- **(U5) の $d$ の側**: 定理 D5 の側。$A_2=t-q$ を明示し、$t=q$ が境界であること、
  および**具体化（$t=1$, $q=1+2^{N+2}$）は $t\ne q$ なのでこの境界に触れない**ことを書いた。

### 2.3 定理 G4 §5.3 の条件 2

本文 (M5) の 2 番目は $M\ge r^\sharp+\max_{P_0}K(P_0)$ で、**訂正後（$+1$ 無し）である**。
さらに原本の訂正が指摘した誤解の元——「層が空でないこと」と「閉形式が成り立つこと」の混同——を
本文に明示した: $M=r^\sharp+\max K$ では非飽和層は空だが、和 $\sum_{s=K+1}^{M-r^\sharp}\varphi(\ell^s)=\ell^{M-r^\sharp}-\ell^K$ は
両辺 $0$ で成り立つので閉形式はそのまま正しく、破れるのは $M<r^\sharp+\max K$ からである。

## 3. cycle 24 step 5 が新たに検出した 2 件の扱い

### 3.1 補題 Q5 の $c_1$ が $b=0$ で未定義 — **入れなかった**

$c_1:=\max\bigl(0,\lceil1+\log_\ell\frac{2b}{\ell-1}\rceil\bigr)$ は $b=0$ で $\log_\ell0$ になり定義されない。
$b=0$ は系 G6（$S_\infty=\emptyset$）で実在する。

**本文へ入れなかった。理由は「塞げないから」ではない。** 塞ぎ方は step 5 が既に示している
（$c_1$ を「$2b<(\ell-1)\ell^{c}$ を満たす最小の自然数」と定義すれば、実対数＝ℝ 脱出も $b=0$ の縮退も同時に消える）。
**入れなかったのは、補題 Q5 が属する定理 Q 系（`cycle21_T3_drop_assumption_B_star.md`）が
そもそも論文本体に 1 ブロックも無いからである**（ラベル一覧に `paper_prop_Q` 系は存在しない。
確認方法は §7）。本章は G 系と D 系だけを運んでおり、$c_1$ が現れる場所が無い。

**したがってこれは「本文の穴」ではなく「未移行の report がまだ持っている穴」である。**
Q 系を本文へ入れる step が来たときに、**上の塞いだ形で入れること。** 申し送りとして §9 に書く。

### 3.2 定理 G2 $(3.2)$ の $m^\sharp_k=\infty$ の読み方 — **穴を塞いだ形で入れた**

$m^\sharp_k=\infty$（$m<\theta^\sharp_k$ に非零係数が無い）のとき $\theta^\sharp_k-m^\sharp_k$ をどう読むかが原本に無い。

本文 (M1) の 2 番目に**読み方と、その理由まで**書いた: 差を $-\infty$ と読み、
**この不等式は自動的に満たされる**。理由は、証明でこの差が使われるのは
「$m<\theta^\sharp_k$ かつ $A^{[k]}_m\ne0$ の項が最小を奪わない」を言うためであり、
そのような $m$ が無ければ条件は空だからである。
(M5) の 4 番目（$M^*$ の条件）にも「$m^\sharp_k=\infty$ の層ではこの不等式は自動的に満たされる」を書いた。

**原本の step 5 が示した別解（和の形 $\frac{\varphi(\ell^M)}{\varphi(\ell^k)}+m^\sharp_k>\theta^\sharp_k$ で書けば規約が要らない）は採らなかった。**
理由は、本文が既に $(\Lambda_k,\theta^\sharp_k,m^\sharp_k)$ の 3 つ組を定義として置いており、
差の形のほうが原本 $(3.2)$ との対応が 1 対 1 で読めるからである。
**どちらの読みも一致する**ことは step 5 が Lean で確かめている（`G2_cond32_sum_form_top`）ので、
この選択は数学的内容を変えていない。

### 4.2 免除 0 件をどう読むか（自分に都合よく読まない）

**「免除 0 件だから転記が完全だ」とは言えない。** 検査 A が見るのは
「条件文に出てくるアトムと語が本文にも出てくること」であって、主張が同じであることではない。

## 8. 自分が犯した誤り（隠さず記録する）

### 8.1 「ℝ を使わない」と書くのに $\mathbb{R}$ を数式ノードで書いた

§5.1 の段落を最初に書いたとき、末尾を「したがって本命題は $\mathbb{R}$ へ脱出しない」と
**`math` ノード**で書いた。実行時検証が即座に赤にした:

```
010_general_closed_form.ts:paper_111_theorem_general_closed_form は可算側の habitat "Qbar" を
宣言しているのに、数式に非可算（ℝ/ℂ）が現れている: \mathbb{R}
```

**検査は正しい。** この検査は数式に現れる集合で住処を判定しており、
「脱出しないと**述べる**ために名前を出す」場合と「実際に使う」場合を区別しない。
区別を検査に持ち込めば、本当の脱出を「言及しているだけ」と称して隠す穴になる。
地の文の「実数体」に書き換えて解決した。**先行章（004・005c）が同じ内容を地の文で書いていたのは、
この理由だったと後から分かった。先に既存章の書き方を読んでから書くべきだった。**

### 8.2 強調がノードをまたいでいて PDF 生成が落ちた

同じ段落で `"**(M2) の "` … `" の冪の比較だけで決まる。**"` と、
$\text{強調}$ を数式ノードをまたいで書いた。英語版の tex 生成が
「対応の取れない `**` が地の文にある（PDF にアスタリスクがそのまま出る）」で落ちた。
強調を最後の 1 ノードの中で閉じる形に直した。

**ここで見落としかけたことがある。** 日本語版は同じ書き方で**落ちなかった**（`applyBold` が
edition ごとに有効・無効を切り替えるため）。「日本語で通ったから正しい」と読むと、
投稿稿である英語版でだけ壊れる書き方を本文に残すことになる。
**日英で検査の掛かり方が違う箇所がある**、というのがここで得た一次情報である。

### 8.3 検証コマンドを間違ったディレクトリで走らせた

`verify-check-linkage.ts` を `integrable-lattice/` で走らせた後、そのままのカレントディレクトリで
`npm run build:pdf` を叩き、`package.json` が無いという ENOENT で失敗した。
**しかもパイプの後ろで `echo "ja exit=$?"` を取っていたため `$?` が `tail` の終了コードを拾い、
`exit=0` と表示された。**失敗が成功に見えていた。
出力本文を読んだので気付いたが、**終了コードの取り方を間違えると検査が黙って緑になる**。
`${PIPESTATUS[0]}` に直した。この type の誤りは、cycle 24 step 3 §9.1
（「赤くなった」で満足すると経路を見落とす）と同じ形である。
