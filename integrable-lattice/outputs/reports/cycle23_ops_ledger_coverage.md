## 5. 台帳に載せても照合力が 0 のブロックが 5 件ある（黙って緑にしない）

検査 A は report の range のうち**条件・例外・仮定を述べている文**だけを見る（`CONDITION_MARKERS`）。
range にその目印を含む文が 1 つも無いと、照合するアトムも語も 0 件になり、
**「台帳の目印がまだ生きている」ことしか検査していない**状態で緑になる。

該当は 5 件:

```
paper_023_definition_massieu     （seed の帰属台帳は表なので条件文が無い）
paper_045_theorem_lte            （LTE の 4 分岐は「$d\mid L$ なら」の形で、目印に当たらない）
paper_054_remark_limits          （限界の記述は「無い」「分からない」で、目印に当たらない）
paper_072_remark_qp_free         （既出性の判定文が目印に当たらない）
paper_082_remark_formalization   （lean/README.md の該当箇所が手順の記述）
```

**これを隠さないため、`verify-transcription.ts` に集計行を足した。** 実行するたびに

```
照合の内訳: 照合したアトム 124 件・語 163 件 / 免除 91 件 / **照合対象が 0 件だったブロック 5 件**（… id …）
  ↑ これらは台帳の目印が生きていることしか検査していない（range に条件文が無い）。限界として記録すること。
```

が出る。**件数を出さずに緑にするのは「覆った」と読めてしまう**ので、id まで並べる形にした。

射程を伸ばす道は `CONDITION_MARKERS` に「なら」「場合」を足すことだが、
これは全 31 ブロックの照合対象を一気に広げるため、**本 step ではやらない**
（広げた分だけ判定の作業が発生し、判定せずに免除を積むと cycle 21 の例外表がたどった道になる）。
次サイクルの候補として §9 に置く。

## 8. 自分が犯した誤り（隠さず記録する）

### 8.1 cycle 22 report が書き残していた誤りを、そのまま繰り返した

最初、台帳の range を「節ごと」に広く取った（`## 4. 主定理` → `## 5. …` の形）。
結果、未確認が **120 件**出て、その大半は証明の途中式・数値検証の標本範囲・
report 内部の履歴だった。**これは cycle 22 report §10.1 が「最初の検査 A は report の全文と本文を
照合する設計で、使い物にならなかった」として記録していた誤りそのものである。**
一次情報を読んでいたのに、設計の教訓を自分の作業へ適用しなかった。
range を「定理の主張だけ」に狭めて 54 件まで落とした。

### 8.2 根拠 report の選び方を間違え、判定語ばかりを照合させた

エントロピー＝Mahler 測度のブロックの根拠に、最初 `paper001_en_citation_review.md`（引用検証の表）を
指した。表の各行は「一致」「原文書き写し」といった**レビューの判定語**でできているので、
挙がるのは判定語ばかりになった。**一次記録は `cycle13_T1_padic_entropy_generality.md` §2**
（原文の書き写しがある側）であり、そちらへ差し替えたら中身の照合になった。
「その主張の一次記録はどれか」を、report の性格（検証記録か原文記録か）まで見て選ぶ必要があった。

### 8.3 定理 D1 の位置を思い違いして、終了の目印を存在しない見出しにした

退化点の計数（定理 D1）が §4.2 にあると思い込み、終了の目印を `### 4.2 帯の上で` と書いた。
実際は §4.3 の中にあり、ツールが「終了の目印が無い」で例外を投げた。
**台帳が腐ったまま緑にならない設計（cycle 22）が、そのまま自分の誤りを止めた。**

### 8.4 既存の免除理由を、編集のついでに書き換えてしまった

トレース周期の上界のブロックの免除項（採らなかった Cramer 則の経路に現れる付値）の理由文を、
新規追加の編集と一緒に書き換えていた。**この step の担当範囲は台帳の拡張であって既存記述の改稿ではない。**
元の文へ戻した。

### 8.5 「照合力 0」の状態を、最初は緑として受け入れかけた

条件文が 0 文の passage を「登録できたのだから良い」と扱いかけた。
実際には**何も照合していない**ので、台帳の件数だけが増えて検査は強くなっていない。
§5 の集計行を足して、毎回件数と id が出るようにした。
