## 弱点 1: 照合対象が 0 件だったブロック（5 → 0）

### 原因

検査 A は report の範囲から**条件・例外・仮定を述べている文**だけを拾い、
そこに現れるアトムと語を本文と照合する。5 ブロック
（`paper_023_definition_massieu` / `paper_045_theorem_lte` / `paper_054_remark_limits` /
`paper_072_remark_qp_free` / `paper_082_remark_formalization`）は
**range に条件文が 1 文も無く、照合が 0 件で走っていた**。
台帳の目印が生きていることしか見ておらず、**緑なのではなく何も見ていなかった**。

### 直し方: 台帳の `covers` を照合対象へ回す

`covers` は台帳の書き手が「この範囲は本文のこれに当たる」と宣言した文である。
**cycle 25 まで「人が読むためのもの。検査には使わない」と型の doc に書いてあった。**
いまは**条件文が 1 文も取れなかった passage に限り**、ここを照合対象へ回す。
台帳が「この範囲は本文のこれに当たる」と言う以上、**そこに現れるアトムと語は本文にあるはずである**。

- `checkCoverage` と `checkExemptionGrounds` の**両方に同じフォールバックを掛けた**。
  片方だけだと、`covers` から出た項目に免除を書いても
  「根拠の引用が report に無い」で落ちて**免除が書けなくなる**。
- **黙って回さない。** `covers` へ回した passage の件数（実測 **28 件**）を毎回印字する。
  回っていること自体は正常だが、「report 本文ではなく台帳の要約と照合している」ことは
  読む側が知っているべきである。

### 出てきた項目 21 件をすべて判定した

新しい照合で **21 件**が「未確認」として挙がった。1 件ずつ本文を読んで判定し、
**機械検証できる根拠つきの免除**として登録した。内訳と代表例:

| 型 | 件数 | 代表例 |
|---|---|---|
| 記法の選択 | 6 | `paper_023` の $\ell_p$・$v_p$——**本文は同じ内容を「素因数分解の指数ベクトルがそのまま $\Lambda$ の元を与える」と語で書いている** |
| 言い換え | 11 | `paper_045_theorem_lte` の「分岐」——本文は 4 つの場合を箇条書きで書き下しており「分岐」という語を使わない |
| 位置づけの言葉 | 4 | `paper_106` の「訂正後」——どの版の $c_1$ かを台帳が断る言葉（後述のとおり最終的に 0 件へ減らした） |

**判定の中身は「台帳の要約が使った分類語」対「本文が書いた内容そのもの」の対応**である。
`covers` は台帳の書き手の要約なので、その語彙（「判定語」「現状表」「明示式」「既出性判定」等）が
本文にそのまま無いのは正常であり、**本文が同じ内容をどう書いているかを `bodyQuote` で pin した**。

## 弱点 2: 機械検証できない免除（14 → 8）

### 原因

`positioning`（「report が自分の作業を位置づける言葉であって主張ではない」）は
**引用が何であっても通った**。「主張ではない」ことは機械で確かめられないので、
件数を出すだけにしていた。**その結果、任意の数学的な文を `positioning` と名乗って黙らせられた。**

### 直し方 (a): 閉じた語彙の目印を必須にした

`POSITIONING_MARKERS`（本サイクル / 本 step / 本ステップ / 本レビュー / 本検証 / 本論文 / 本節 /
副産物 / 訂正 / 以下では / ここでは / 未確認 / 新規性は主張しない / 記録として / 位置づけ）を置き、
**引用がこのどれかを含むことを必須にした**。語彙は
**report が自分（この作業・この文書）について語るときの言い回し**だけで構成し、
数学の内容を指す語は入れない（入れると目印の意味が無くなる）。

これで「ただの数学の文を `positioning` と名乗って黙らせる」ことができなくなった。

### 直し方 (b): 目印を持たなかった 6 件を、機械検証できる型へ付け替えた

導入直後、既存 14 件のうち **6 件が目印を持たず赤くなった**。
**その 6 件は分類が誤っていた**ので、本文を読んで正しい型へ付け替えた:

| ブロック / 項目 | もとの引用 | 付け替え先 | pin した本文 |
|---|---|---|---|
| `paper_055` / 予言 | 「予言に使うのは $\mu$ と $\Lambda$ だけ」 | 言い換え | 「の係数からの有限計算で決まる（塔の値も円分体も使わない）」 |
| `paper_055` / 数値 | 「H4 は上の 3 分解を数値で出している」 | 例示の省略 | 同上 |
| `paper_013` / 有限側・本体軸 | 「**有限側の本体軸**。」 | 本文のほうが弱い主張 | 「**軸 3（複雑性）**: 有限サイズで多項式時間か #P 困難か。」 |
| `paper_051` / 整合 | 「という定義はこの規約と整合しており」 | 言い換え | 「（退化因子を落とす流儀）はこの規約そのものである。」 |
| `paper_063` / 完全 | 「$d=-2$ と完全に決まる」 | 言い換え | 「 の係数からの**有限計算で判定できる**。」 |

**いずれも「本文が同じ内容を持っていること」を `bodyQuote` で機械検証する型である。**
弱点 1 で新たに増えた `positioning` 4 件も同じ方針で付け替え、
**最終的に `positioning` は 8 件**（すべて目印を持つことを検出テストが毎回確認する）。

## 検出の実証

`verify-transcription-detection-test.ts` を **12 → 16 件**に増やした。追加 4 件:

- cycle 23 以来「照合対象 0 件」だった 5 ブロックが、いま何かを照合していること
  （実測: 照合対象 **45 件** / `covers` へ回した passage **9 件**。どちらも 0 なら強化が効いていない）

- 自己言及の語彙を含む引用は通ること（偽陽性でない）
- **現存する `positioning` の免除 8 件がすべて目印を持つこと**

## 限界（正直に書く）

- **`covers` は台帳の書き手の要約である。** report 本文そのものではないので、
  照合の出所としては条件文より弱い。だから**フォールバックであり、件数を毎回出す**。
- **`positioning` の限界は残っている。** 目印を持つ文が「本当に主張ではない」かどうかは
  機械で確かめられない。**8 件は依然として人の判定に依存する。** 件数は毎回出す。
- 免除は 89 → **110 件**に増えた。**免除が増えることは検査を弱めうる**が、
  今回増えた 21 件はいずれも「これまで何も照合していなかった場所」から出たものであり、
  **照合対象（アトム 181→201・語 186→254）のほうが大きく増えている**。
- 検査 A が捕まえられないもの（場合分けの意味の誤り・report 自体の誤り）は変わっていない。

## 私が犯した誤り（隠さず記録する）

1. **`checkCoverage` にだけフォールバックを入れ、`checkExemptionGrounds` に入れ忘れた。**
   その状態では `covers` 由来の項目に免除を書いても「根拠の引用が report に無い」で落ち、
   **免除が書けない＝ずっと赤いまま**になる。実装後すぐ気づいたが、

   結果的に「6 件は分類が誤っていた」という良い発見になったが、それは偶然である。
   **影響範囲を測ってから入れるべきだった。**

   （「**規約（書き落とせない）**」は隣の `paper_111` の本文だった）。
   検査が「根拠として指した本文の記述が本文に無い」で落ちて気づいた——
   **この検査が本 step 自身の誤りを捕まえた**。
