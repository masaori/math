## 2. 設計 — 免除に何を持たせたか

免除は「report のこの文について、本文はこう書いているから、この記号・語を落としてよい」という**判定**である。
判定が寄りかかっている先は 3 か所しかない。**report の文**・**本文の記述**・**別ブロック（分担先）や別 report（記録）**。
そこで免除に、寄りかかり先を機械が辿れる形で書かせる。

```ts
type ExemptionGrounds =
  | { type: "notation";    reportQuote; bodyQuote }                    // 記法の選択
  | { type: "weaker";      reportQuote; bodyQuote }                    // 本文のほうが弱い主張
  | { type: "division";    reportQuote; holder; holderItem }           // ブロック間の分担
  | { type: "positioning"; reportQuote }                               // report の位置づけの言葉
  | { type: "example";     reportQuote; bodyQuote }                    // 例示の省略
  | { type: "paraphrase";  reportQuote; bodyQuote }                    // 言い換え
  | { type: "reportStale"; reportQuote; supersededBy: {report, marker} }// report のほうが古い
  | { type: "bodyDefect";  reportQuote; recordedIn:  {report, marker} };// 本文の不備（記録済み）
```

型は cycle 23 report §4 が 54 件を 1 件ずつ判定したときに使った 8 分類をそのまま持ち込んだ（分類を作り直していない）。

**すべての型に共通の検査（検査 A′）**:

1. `reportQuote` が、その免除が属する passage の**条件文のちょうど 1 文**に当たること。
   - 当たらない → 「根拠の引用が report に無い」。**report が書き換わったら赤になる。**
   - 2 文以上に当たる → 「複数の文に当たる」。定型句（「(H) を仮定し、塔が**非退化**」等）は
     pin になっていないので根拠として認めない。
2. **その文から実際にその項目（アトム／語）が出る**こと。抽出は検査 A と**同じ関数**を使う
   （別に書くと「根拠として指した文からその項目が出ない」状態が緑で通る）。
   - 出ない → 「根拠の文からその項目が出ない」。**別の文を貼っていたら赤になる。**
3. 引用が短すぎないこと（12 文字以上）。ただし**条件文 1 文と完全一致する引用は短くてよい**
   （report には「無条件決定可能。」のような 8 文字の文が実在する。§9.2）。

**型ごとの追加検査**は §3 の表のとおり。

集計行は毎回出る（cycle 23 の「照合力 0 のブロック 5 件」と同じ思想で、**件数を出さずに緑にしない**）:

```
[検査 A′] 免除の根拠が生きているか — 内訳
  免除 91 件 / 型別: 言い換え 23・例示の省略 5・記法の選択 17・ブロック間の分担 11・本文のほうが弱い主張 19・
                     report の位置づけの言葉 14・本文の不備（記録済み） 1・report のほうが古い 1
  根拠未指定 0 件（型で強制。根拠なしの免除は書けない）/ **失効した免除 0 件** /
  **型として機械検証できないもの 14 件**（report の位置づけの言葉）
```

## 3. 型ごとの検出可否（できないものは「できない」と書く）

| 型 | 件数 | どう腐るか | 機械検出 |
|---|---|---|---|
| **ブロック間の分担** `division` | 11 | 分担先のブロックがその項目を失う／ブロックごと消える | **◎ 最も強い。**「論文全体では内容が残っている」ことを実際に確かめられる唯一の型。分担先を検査するので、**どのブロックも自分の担当しか見ていない状況で誰も気付かない脱落**を捕まえる |
| **記法の選択** `notation` | 17 | 本文が採っている書き方が消える | **○** report 側の pin ＋ 本文側の記述の実在。両側が生きていることを見る |
| **report のほうが古い** `reportStale` | 1 | 解消した側の記録が消える／古い側の文が動く | **○** 2 本の report を両方 pin する（前後関係が根拠なので片側では足りない） |
| **本文の不備（記録済み）** `bodyDefect` | 1 | 記録が消える | **○** 記録を pin。加えて**本文が直れば既存の「免除が余っている」検査が赤にする**ので、両方向が閉じている |
| **本文のほうが弱い主張** `weaker` | 19 | 本文の弱い側の記述が消える | **△** 両側の実在は見る。**「弱い」という含意関係そのものは機械検証できない**（強い主張を落としてよい理由は人の判断） |
| **言い換え** `paraphrase` | 23 | 言い換え先の本文の記述が消える | **△** 実在は見る。**「同じ主張である」ことは機械検証できない** |
| **例示の省略** `example` | 5 | 主張を担う本文の記述が消える | **△** 実在は見る。**「例が無くても主張が保たれる」ことは機械検証できない** |
| **report の位置づけの言葉** `positioning` | 14 | report の文が動く | **✕ 検出できない。**「これは主張ではない」という判定そのものを機械で確かめる手段が無い。引用 pin しか掛かっていない。**毎回件数を出力する** |

**要点**: 91 件のうち、**根拠の両側（report と本文）を機械で辿れるのは 76 件**、
**片側（report の pin）だけなのが 14 件**（`positioning`）、
**分担先まで辿って「論文から消えていないこと」を確かめられるのが 11 件**である。
`weaker` / `paraphrase` / `example` の 47 件は、**両側が生きていることは確かめられるが、
その 2 つの関係（含意・同値・一般化）は確かめられない**。ここは Lean 化の領分であって、この検査の外である
（cycle 22 の限界 1「転記検査は Lean 化の代わりにならない」は動いていない）。

## 5. 移行方針と、実際に赤くなった件数

**方針**: 既存 91 件を 1 件ずつ、cycle 23 report §4 が記録した判定の型へ割り当て、
その型が要求する根拠を書く。**根拠は自動生成でごまかさない**——
`reportQuote` は「その免除を生んだ条件文」を実際に走らせて特定した文から取り、
`bodyQuote` / `holder` / `holderItem` / `marker` は**既存の `reason` が何を言っているかを読んで**人手で決めた。

**赤くなったのは 1 件である。**

| # | 免除 | 何が赤になったか | 対処 |
|---|---|---|---|
| 1 | エントロピー＝Mahler 測度のブロック（`paper_031_theorem_lsw`）の「無条件」 | 「根拠の指定が短すぎて何も pin していない」。引用「に対して無条件に掲げ」が 10 文字で、report の別の箇所にも当たりうる | 引用を「$\mathfrak a=\langle f\rangle$（$f\neq0$）に対して無条件に掲げ」へ伸ばした。判定の中身は変えていない |

**この 1 件は「腐っていた免除」ではなく、私の書き方の誤りである。**
そして**既に腐っていた免除は 0 件**だった。

**これを「免除 91 件は健全だった」と読んではならない。**
根拠を**現在の report と現在の本文から**起こしている以上、その時点で全件が通るのは当然である。
移行が測れるのは「根拠を書けるか」であって「免除が正しいか」ではない。
**検査の値打ちは、これから report や本文が動いたときに出る。** それを測ったのが §6・§7 である。

## 9. 自分が犯した誤り（隠さず記録する）

### 9.1 検出テストで、通したい検査経路と違う経路を通していた（2 回）

「引用は当たるが、その文はその項目を生まない」の再現データを作るとき、
**本文にしか無い文字列**を report の引用として指定した。テストは赤になったが、
出た違反は「根拠の引用が report に無い」であって、**確かめたかった経路（項目が出ない）は 1 度も通っていなかった。**
期待する違反の種類まで突き合わせる形にしてあったのでテストが失敗し、気付いた。

**同じ誤りを同じサイクル内でもう 1 回やった。**「引用が複数の文に当たる」の再現データで
`"(H) を仮定し"`（9 文字）を使い、短すぎ判定に先に捕まっていた。
**「赤くなった」で満足すると、どの経路で赤くなったのかを見落とす。**
期待する違反の種類を再現データに書かせる設計にしていなければ、両方とも緑（＝実証したつもり）で通っていた。

### 9.2 閾値を先に決めて、一次情報を後から見た

引用の最短文字数を 12 文字と決めてから 91 件を書き始めた。ところが report の条件文には
「無条件決定可能。」のような**8 文字の文が実在する**（`inputs/seeds/lambda-statement-program.md`）。
文全体を引用しても閾値に届かない。
