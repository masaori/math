# 「射程の主張」を機械で支える道を作り、記号の穴を測って結論を出した（cycle 32 step 4）

本文と `lean/` は 1 文字も変えていない。

## 前半: 「射程の主張」は機械で支えられた（4 件中 4 件）

### 何が問題だったか

cycle 31 step 4 は、台帳の「無い」の根拠を数字まで読む検査を入れ、
**不在を主張している 9 エントリのうち機械が再確認できているのは 5 件**だと実測した。
残り 4 件を 1 件ずつ読むと、いずれも「無い」ではなく**「在るが射程が足りない」型**だった。
**語の件数ではこの型を支えられない。語は当たるからである。**
cycle 31 はそこを違反にせず、「射程を型のある形にする設計が要る」を送った。

### 何をしたか: 漠然とした「射程」を、確かめられる 3 つの形へ落とした

**現に台帳にある主張から逆算した**（原理から出したものではない。検査 Λ の 3 規則と同じ立て方）。

1. **宣言が仮定を要求する** — その名前は在るが、宣言が強い仮定の下にある。
   確かめ方: その宣言を含むファイルで、宣言より前の `variable` 行にその仮定が書かれていること。
2. **在るが概念を使っていない** — そのファイルは在るが、要る概念を 1 度も使っていない。
   確かめ方: ファイルが在り、その語が 1 度も現れないこと。
3. **在るが関係が無い** — その名前は在るが、要る関係と一緒に現れる行が無い。
   確かめ方: 語 A が在り、かつ語 A と語 B が同じ行に現れる箇所が 0 件であること。

### 実測（この step の答えの本体）

**登録 4 件、裏が取れた 4 件、反証された 0 件。**

| 主張 | 形 | 機械が確かめたこと |
|---|---|---|
| 可換環の上の Euler の双対基底公式が無い | 宣言が仮定を要求する | `Module.Basis.traceDual` は `[Algebra.IsSeparable K L]`・`[FiniteDimensional K L]` の下にある |
| 多変数の Mahler 測度が無い（解析側） | 在るが概念を使っていない | そのファイルは在るが `MvPolynomial` が 0 件 |
| 多変数の Mahler 測度が無い（数論側） | 在るが概念を使っていない | 同上 |
| 単因子の整除の鎖が無い | 在るが関係が無い | `smithCoeffs` は 18 行に在るが、整除記号と同じ行は 0 件 |

**これで、人の読みに依っていた 4 件のうち 3 件（重複を除くと 3 つの主張）が機械の側へ移った。**

### 実測が台帳の言い方を 1 つ正した

台帳は Euler の件について「**宣言行で直読した**」と書いていたが、
**実際に仮定を持っているのは宣言行ではなく節の `variable` 行である**
（`Module.Basis.traceDual` の宣言行は `noncomputable def Module.Basis.traceDual :` だけである）。
主張の中身は変わらないが、言い方が緩かった。検査はこの形（`variable` 行も見る）に合わせて作り、
台帳の記述も直した。

### 違反にする条件と、しない条件

- **反証されたときだけ違反にする**——仮定が見つからない／不在と言った語が在る／
  無いと言った組合せが在る／在ると言った宣言が無い。
- **確かめられなかった場合は違反にしない。** `npm run check` は
  **mathlib がこの作業ツリーに無くても通る前提**で運用しているためである（cycle 31 と同じ判断）。
  確かめられなかった件数は毎回印字する。

検出テストは **9 件**（通るべき 3 つの形と、反証される 5 つの形、および mathlib 不在の形）。
`npm run check` は 32 → **33 段**。

## 後半: 記号の穴は他の記号にもあるか——測った。結論は「同じ規則は移せない」

cycle 31 は検査 Λ の限界として
「台帳にあるブロックの中で裸の $\Lambda$ を別の量に使うことは止められない」と書き、
**同じ穴が他の中心記号にもあるかを測るかどうか**を cycle 32 へ送った。**測った。**

### 実測

日本語版の本文での出現回数（英語版もほぼ同数）:

| 記号 | 出現 | 指している量 |
|---|---|---|
| $\ell$ | 1335 | 固定した素数（ほぼ全部）／素数 $p$ の対数 $\ell_p\in\Lambda$（4 件）／Monsky の係数 $\ell_0$（2 件） |
| $\theta$ | 263 | 消滅深度と、その変種（$\hat\theta_M$・$\theta_G$ 等） |
| $\mu$ | 70 | 岩澤不変量と、その変種 |
| $\Lambda$ | 10 | 対数順序群のみ（cycle 31 で改名済み） |

**$\ell$ には形の上で同じ穴がある**——1 つの字が 3 つの量を指している。

### それでも検査 Λ の規則は移せない（これが本 step の判断）

**$\Lambda$ の事故と $\ell$ の状況は、飾りの意味が逆である。**

- $\Lambda$ では、**飾りを付けること自体が衝突の徴候**だった
  （$\Lambda(r)$ や $\Lambda_k$ が対数順序群でない別の量を指していた）。
  だから検査 Λ は「飾りを付けない」を規則にできた。
- $\ell$ では、**飾りが正当な区別の手段**である。
  $\ell_p$ は対数順序群の定義そのもの（$\Lambda=\bigoplus_p\mathbb{Z}\ell_p$）が使う記法であり、
  $\ell_0$ は Monsky の論文の記法を引用したものである（外部文献の記法をそのまま使うのは規約の例外）。

**したがって「飾りを付けない」を $\ell$ へ移すと、正しい記法が全部赤くなる。**
移せるとしたら別の形——**どの飾りが許され、それぞれが何を指すかを台帳で持つ**形になる。
それは検査 Λ の 3 規則より大きな設計であり、本 step では作っていない。

**結論: 測った結果、同じ穴は $\ell$ に在るが、同じ規則では塞げない。**
塞ぐなら記号ごとの意味の台帳が要る。**作るかどうかは次サイクル以降の判断とする**
（作れば $\ell$ の 1335 出現すべてに意味の宣言が要ることになるので、
費用対効果はユーザーの価値判断に触れる。ここでは決めない）。
