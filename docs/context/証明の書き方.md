# 数学レイヤー: 証明の書き方

**証明をどう書き、どう検証するか**についての規律。全プロジェクトに適用する。

## 先に一点（最も誤読されやすい）

> **人手証明は具体に固定する。抽象化は Lean の中だけで行う。**

「抽象度を上げない」（人手証明）と「必要十分な抽象度まで上げる」（Lean）は逆向きに見えるが、
**適用先が違う**。この一点を取り違えると、人手証明が読めなくなるか、
Lean が既製の一般論への丸投げになる。実際に一度事故が起きている。

## ゴール

**丁寧に一つずつ積み重ねて読めば、高校生でも理解できる形で書く。**

これは「厳密であること」と同格の要求であり、**厳密だが読めない証明は失敗**とみなす。

避けたいのは、高い抽象度の道具を持ち込んだせいでその一般論を先に理解する必要が生じ、
**本筋と関係ないところで読者のリソースが尽きること**である。

## 記述の規律

| 規律 | 内容 |
|---|---|
| **一ステップ一定理** | 式変形を絶対に省略しない。移項も四則演算も含め、1 ステップに 1 つの定理・操作しか適用しない。**同じ定理を複数箇所へ同時適用する場合だけ** 1 ステップにまとめてよい |
| **式変形は一続き** | **式変形と式変形の間に日本語を挟まない。** 等号でつなげられるものは、途中に文章を入れず 1 つの整列した式にする。求めたい値から始め、1 行に 1 つの等号を置き、最後の値までたどり着く（下記「式変形の書き方」） |
| **根拠の明示** | すべての行に、適用した定理・操作を書く。**書く場所はその行の末尾で、$(\because\ \dots)$ の形にする**（「〜により」という日本語の説明文にしない）。高校教科書レベルで自明なもの（四則・分配則・移項）は省略してよい。**本文で証明済みの Definition / Claim / Theorem の適用は、同じ証明中に何度現れても必ずラベル参照で引く** |
| **階層の可視化** | 根号・分数・行列・場合分けのネストは必ずインデントで表す。フラットな一行に潰さない |
| **Step 分割** | **独立した中間目標が複数ある場合にだけ** Step で切り、各 Step を一つの中間目標に対応させる。等号でつなげられるものを Step に割って日本語で継がない |
| **記号の帰属** | 登場するすべての記号について所属集合を書く（$\mathbb{N}/\mathbb{Z}/\mathbb{Q}/\Lambda/\overline{\mathbb{Q}}/\mathbb{R}/\mathbb{C}$）。$\mathbb{R}$ が現れる行には**その理由**を添える（指数評価か、極限か、実対数か、完備性か） |
| **1 ブロック 1 主張** | **1 つのブロックに定義や主張を 2 つ以上入れない。** 「定義（スピン値の番号と、行配位の辞書式順序）」のように 2 つを束ねると、番号が 1 つしか付かず**あとから片方だけを引けない**。定義が 2 つあればブロックを 2 つにする。主張が「$A$ かつ $B$」の形なら、$B$ が $A$ の言い換えでない限り分ける |
| **同一視をしない** | **「〜とみなす」と書かない。** 2 つの集合の元を同じものとして扱うには、**その間の写像を定義して名前を付ける**しかない。名前を付けずに済ませた同一視は、記号の濫用と同じ種類の曖昧さを増やす（下記「同一視は写像を定義してからでないとできない」） |

### 式変形の書き方

求めたい値から始めて、1 行 1 等号でつなぎ、根拠は行末に $(\because\ \dots)$ で書く。

```text
Φ_L(1) = log Z_L(1)                        (∵ 有限系の自由エントロピーの定義)
       = log( Σ_m Ω_L(m)·1^m )              (∵ 分配多項式の係数は多重度である)
       = log( Σ_m Ω_L(m) )                  (∵ 1^m = 1)
       = log( 2^{L²} )                      (∵ 多重度の総和は配位の総数に等しい)
       = L² · log 2                         (∵ 対数の冪の法則)
       = L² · ℓ_2                           (∵ 2 は素数)
```

### なぜここまで厳格にするのか

**数式の前後に置いた日本語は、必ず曖昧さを持ち込むからである。**

- **どのトークンについての説明かが確定しない。** 「これを代入して」「右辺を並べ替えて」と書いた瞬間、
  どの記号を指しているかは読み手の推測に委ねられる。
- **論理の依存関係が明示されない。** 自然言語である以上、何が何から従うのかは文の順序と接続詞に
  暗黙に載るだけで、形式として書かれていない。
- **書き手はこれを曖昧さだと感じない。** 日本語で説明を足すと丁寧になった気がするが、
  増えているのは分量であって確定した情報ではない。

**結局、すべてが数式だけの式変形の連続として書けているときが最も曖昧さがない。**

> **数学者にとって「読みやすい」とは、曖昧さがないことである。**
> 日本語でそれらしく説明することは、読みやすさではなく曖昧さの追加でしかない。できるだけ避ける。

この規律は、[方法論レイヤー](成果の出し方.md)の要求とも一致する。曖昧さを含む証明は
SageMath にも Lean にも落とせない。人手証明の段階で曖昧さを残すと、形式化の段階で
「人手証明のどれを形式化したのか」が決まらなくなり、四層の検証が意味を失う。

加えてこの形は次の 2 つを与える。**証明の骨格が一目で見えること**（どの値から始まり
どの値に着くかが 1 か所に並ぶ）。そして**一ステップ一定理が守られているかを目で確認できること**
（1 行に 1 つの等号と 1 つの根拠しか書けないので、複数の定理をまとめて適用すると形が崩れて分かる）。

- **準備と式変形を混ぜない。** 証明の中だけで使う記号を置く、補助的な等式を先に作る、といった
  作業は式変形ではない。**証明の冒頭にまとめて置き**、そのあとで目的の量から始まる 1 つの式変形を見せる。
  準備を Step 1・Step 2 と番号で並べて式変形と地続きに見せると、**議論が行ったり来たりして読めなくなる**。
  記号を置くだけなら $B(\sigma):=\dots$ と定義を書き、改行して $b(\sigma)=|B(\sigma)|\ (\because\ \dots)$ と
  続ければよい。
- **式変形は主張の左辺から始める。** 主張が $b(\sigma)=\dots$ なら $b(\sigma)$ から始めて右辺へ着く。
  途中の量から始めて最後に主張へ組み立て直す書き方をしない。
- 一続きにできない議論（場合分け、集合の等号を両包含で示す、存在の構成など）は無理につながない。
  **その中に現れる計算は、この形で一続きに書く。**
- $(\because\ \dots)$ は数式の中なのでラベル参照を張れない。**引いたブロックは式の直後に
  ラベル参照でまとめて挙げる**（上表「根拠の明示」の要求を満たし、改名で参照が切れたことを
  機械が検出できるようにするため）。

### 同一視は写像を定義してからでないとできない

**「$A$ の元を $B$ の元とみなす」と書いてはならない。** 同一視とは本来、$A$ から $B$ への写像
（多くは単射、または全単射）を定義して初めて成立するものである。写像に名前が付いていなければ、
どちらの集合で計算しているのか、どの演算を使ったのかが式に書かれない。
これは記号の濫用と同じ種類の曖昧さであり、同じ理由で避ける。

やり方は決まっている。**行き来する写像に名前を与え、その 2 本以外の経路で往復しない。**

```text
悪い: 「{0,1,…,L-1} の元を Z/LZ の元とみなす」。i+1 の加法がどちらのものか式に書かれない
良い: π: Z → Z/LZ（自然な射影）、s: Z/LZ → Z（代表。0 ≤ s(y) ≤ L-1 かつ π(s(y)) = y）を定義し、
      以後この 2 本だけを通る。Z/LZ の加法は +_{Z/LZ} と書き、1̄ := π(1) と 1 を区別する
```

同じ理由で、**同じ記号を 2 つの集合の元として使い回さない**。$i$ を整数としても剰余類としても
使うのをやめ、どちらか一方に固定して、他方は写像の像として書く。

この規律は $\mathbb{Z}$ と $\mathbb{Z}/L\mathbb{Z}$ に限らない。多項式とその値、有限集合と
その添字集合、群とその表現など、「同じもののように扱いたくなる 2 つ」すべてに適用する。

### 新しい道具を入れるときの判断

1. これを理解しないと先へ進めないか。そうでないなら入れない。
2. 本筋か脇道か。脇道の一般論なら具体的な形に落として本文に書く。
3. より初等的に書けるか。書けるならそちらを採る（記述が長くなっても構わない）。
4. 入れるなら、その定義は本文にあるか。**暗黙に使われる未定義の概念を残さない。**

### 抽象度を上げない（人手証明）

主張は具体的な対象について述べる。一般の環・体へ持ち上げない。
理由は、証明が分配則と結合則しか使っていなくても、**述べ方が抽象的なら読者の負担は発生する**から。
「任意の環で成り立つ」と書けば、読者は環の定義と「この対象が環をなすこと」を先に要求される。

## 四層の検証（上の層が下の層を検査する）

| 層 | 何をするか | 何を保証するか |
|---|---|---|
| **記述** | 上の規律で人手証明を書く | 人が一行ずつ追える。省略に嘘が隠れない |
| **SageMath 検証** | 式変形を**一行ずつ**機械に確かめさせる | 書き間違い・符号ミスが残らない |
| **Lean 具体版** | 人手証明と **1 対 1 に対応する**証明 | **人手証明そのものが正しい** |
| **Lean 必要十分版** | 同じ手順のまま抽象度だけ必要十分まで上げる | **何が本質的か**。具体版が過剰な構造を要求していないかの検査 |

### SageMath 検証

- 対象は**ラベル**で紐づける（ファイルパスに依存させない）。`overview.md` に対象ラベルを宣言する。
- **厳密計算を優先する。** `ZZ`/`QQ`/`QQbar`・素因数分解で行い、浮動小数点は
  $\mathbb{R}$ 脱出を含む量を確認するときだけ使う。使ったら理由を記録する。
- 検証が失敗したら**人手証明を直す。** 検証を主張に合わせて緩めない。失敗の記録は消さない。

### Lean 具体版

- 抽象度は人手証明と同じに固定する。
- 人手証明のどのステップが Lean のどの補題かをコメントで対応づける。
- **人手証明の計算を mathlib の一般論へ委ねない。** 委ねた時点で 1 対 1 対応の要件違反。
- `sorry` を残さない。

### Lean 必要十分版

目的は二つ。**何が本質的かを示すこと**（「任意の環で通るなら、行列であることも複素数であることも
本質的でない」）と、**具体版の検査**（必要以上の構造を仮定しないと通らないなら、具体版が
余計な性質に依存している疑いがある）。

満たさないものは必要十分版と認めない:

1. **証明手順が具体版と同じ**であること。別の論法に差し替えたものは、主張が同じでも認めない。
2. **仮定が「具体版の証明が実際に使っている性質」だけ**であること。
   削ったせいで通らなくなった仮定は残し、**なぜ必要かをコメントに書く**（これが検査の本体）。
3. **mathlib の高抽象度の既製定理へ丸投げしない。** 一行で終わる宣言や単なる別名定義は認めない。
   既製定理との一致を見たいなら、自前の証明を書いたうえで一致を述べる補題を一本だけ添える。
4. **具体版が必要十分版の特殊化として得られること**を導出側に明示する。
5. **必要十分版は Lean の中だけに置く。** 人手証明にも参照用ノートにも持ち込まない。
6. 上の 1–3 は**具体版にも対称に適用する**。

> **名称の注意**: かつて「抽象版」と呼んでいたが、その名が「抽象的な概念を持ち込んで
> 証明し直すこと」と誤解され、mathlib へ丸投げしただけのファイルが書かれる事故が起きた。
> 意図は抽象化そのものではなく**必要十分性の見極め**なので「必要十分版」と呼ぶ。
> 実装上の名前空間・ディレクトリの規約は
> [`exact-solution-of-2d-ising-model/README.md`](../../exact-solution-of-2d-ising-model/README.md) を正本とする。

## 補助規律

- **正しさに必要ならそれは注記ではない。** 定義が意味をもつ条件・適用範囲・well-defined 性・
  主張から従う帰結は本文に書く。補足計算・具体例・物理的解釈・先行研究との比較はノートへ。
- **採用しなかった経路は捨てない。** 参照用ノートへ移し、**採用しなかった理由を明記する**。
  後から「なぜこの道を選ばなかったか」を再検討できるようにするため。
- **移行・書き換えのとき、ブロック数や参照解決だけを見て完了と判断しない。**
  証明の中身が原本から確実に運ばれたかを突き合わせる（過去に主要定理の証明を失った事故がある）。

## 適用範囲

- 命題・定理として主張するものには四層すべてを適用する（Lean は `lean/` を持つプロジェクトのみ）。
- 探索フェーズ（調査ノート・アイディアの種）は対象外。Markdown で速く回してよい。
  ただし**命題へ昇格させる時点で**記述の規律と記号の帰属を適用する。
  **対象外にならない下限が 3 つある**（下記「探索フェーズでも守る下限」）。
- 四層を全部満たせない段階では、**どこまで済んでいるかを明示する**（「記述と SageMath まで。Lean 未着手」）。
  黙って未検証のまま「証明した」と書かない。

## 探索フェーズでも守る下限

上の適用範囲で探索フェーズを対象外にしたのは、**一ステップ一定理と四層の検証**についてである。
**次の 3 つは探索フェーズでも守る。** 速く回してよいのは自分の仮説であって、既存の数学の引用ではない。

### 定義が定まっていない段階で結論を書かない

**既存の数学の定義・定理に言及するときは、定義を確定してから書く。**
確定していない段階で「〜とは〜のことである」「したがって〜と〜は同値である」と書かない。

**実際に事故が起きている。** セルオートマトンのプロジェクトの調査文書で、
無限体積 Gibbs 測度の定義を置かないまま「極限の非一意性がそのまま相転移の定義である」と書き、
二度訂正する結果になった。相転移には**同値でない 2 つの定義**（相共存と自由エネルギーの非解析性）があり、
書いたものは一方としか一致していなかった。定義を置いていれば書く前に分かったことである。

守り方は決まっている。**定義と定理だけを書いた文書を分け、仮説はそこから参照する。**
仮説と定義を同じ文書に混ぜると、どこまでが確立した内容でどこからが推測かが読み手に分からなくなる。
**書き手にも分からなくなる。**

### 物理の文脈で通じる書き方では足りない

**このリポジトリは物理を論じる場ではない。** 可算の立場から、
物理に役立つ可能性のある数学を探すのが目的である（[理論物理レイヤー](物理を記述する数学の選び方.md)）。
したがって、**物理の文脈でなら正しく機能する程度の書き方には、ここでは価値がない。**

「相転移とは秩序が生じることである」「臨界点では相関長が発散する」といった文は、
物理では通じるが、ここでは何も定めていないのと同じである。
記号がどの集合の元か、演算がどう定義されるか、極限がどの位相での収束か、
$\mathbb{R}$ をどこで使ったかが書かれていない主張は、**主張として成立していない**とみなす。

これは上表「記号の帰属」の要求を、探索フェーズの散文へ広げたものである。

### 出典の格付けを書く

二次情報（教科書・レビュー・検索結果・要旨）に基づく記述には、**原論文未確認であることを明記する。**
確認済みのものと同じ書き方をしない。既存研究に「見つからなかった」ことを
「存在しない」と書かないのも同じ規律である。
