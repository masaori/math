# 成果の出し方（方法論レイヤー）

**なぜこの研究を我々がやるのか、どうやって価値を出すのか**についての立場。
道具の進化とともに変わりうるので、三レイヤーの中では最も可変である。

## 我々が持っている技術的アドバンテージ

**AI × SageMath × Lean** の組み合わせにより、**人間だけでは物量的に不可能だった探索と検証**を回せる。

| 道具 | 担当 | 効くこと |
|---|---|---|
| AI | 探索の幅と物量 | 候補生成、文献横断、機械的な書き下し、総当たり検査 |
| SageMath | 厳密計算 | `ZZ`/`QQ`/`QQbar`・素因数分解。**丸めが原理的に入らない** |
| Lean | 形式検証 | 人手証明の正当性保証と、何が本質かの見極め |

## なぜこれが理論物理レイヤーと噛み合うのか（この方針の骨格）

> **機械が信頼できるのは、等号が決定可能な世界だけである。**

$\mathbb{R}$ の等号は決定不能。$\Lambda$ の等号は素因数分解の一致。$\overline{\mathbb{Q}}$ の等号は根分離。
すなわち

**我々の技術的優位が存在する領域と、
[理論物理レイヤー](物理を記述する数学の選び方.md)が「物理の実体がある」と考える領域は、同じ領域である。**

哲学が先にあって道具が後から来たのでも、道具があるから哲学を後付けしたのでもない。
**同じ境界線を別方向から指している。** この一致がこの研究方針の骨格であり、
単なる趣味ではなく戦略として成立している根拠である。

## なぜ $\mathbb{R}$ 側で戦わないのか

**$\mathbb{R}$ が劣っているからではない。** むしろ逆で、実数・複素数は多くの天才によって
性質をほぼ丸裸にされた成熟した道具であり、今後活躍する天才たちもその使い方に極めて馴染んでいる。
**人類の武器としては依然きわめて強力である。**

だからこそ、そこで我々が物量をかけても勝てない。実解析・関数解析の蓄積と人的資本が
圧倒的だからである。**同じ事実が、$\mathbb{R}$ が強い理由であり、我々がそこで戦わない理由でもある。**

対して可算側は**蓄積が薄く、かつ機械が効く。** ここに我々の比較優位がある。

## 標的の選び方

物量は手段であって主張ではない。**標的の選び方がすべてである。** 標的は次の二つを同時に満たすこと。

1. **機械にかけられる形になっているか** — 決定可能・厳密計算可能・witness を提示できる。
2. **数学・物理として意味があるか** — 既存研究と差分があり、内容が空でない。

片方だけでは価値がない。1 だけなら「計算しただけ」、2 だけなら我々がやる理由がない。

**出す成果は「大量に計算した」ではなく「可算側で厳密に述べ直された命題」である。**

## ガードレール

- **物量そのものに価値があるのではない。** ツールとしての優位を持っているがゆえに、
  他では出しにくい成果が出せるはず、というだけである。物量を成果と言い換えない。
- **AI が最もごまかしやすいのは検証の層である。** 特に Lean の必要十分版は、
  mathlib の既製定理へ丸投げすれば形だけ整う。禁止事項は
  [証明の書き方.md](証明の書き方.md) に明示してある。
- **数値検証が通ったことを証明と呼ばない。** SageMath は式変形の裏取りであって証明ではない。
- **調査の限界を正直に書く。** 「先行研究が無い」は「見つからなかった」の意味であり、
  存在しないことの証明ではない。既読／未読を区別して記録する。

## 立場の自覚

- 趣味として数学・物理をやっており、既存コミュニティのワークフローに縛られない位置にいる。
  だからこそ前提の逆転を試せる。この自覚は持っておく。
- 一方で、**AI と機械検証の発達により既存のワークフローそのものが崩れつつあるのは、
  大きなトレンドとして明らか**であり、この立場は個人的な偏りに留まらない。
  形式化の実例（四色定理、Flyspeck、Liquid Tensor Experiment、Lean による大規模形式化）が
  すでに積み上がっている。
- したがって**外向きには「前提の逆転」ではなく「決定可能な可算コアの同定」として提示する。**
  立場を共有しない読者にも通用する形にしておく（[理論物理レイヤー](物理を記述する数学の選び方.md)
  の「前提と成果物を分離する」）。

## 作業の型

1. **探索** — AI で広く候補を出す。この段階は Markdown で速く回す。反証可能な形（潰れ方を書く）にする。
2. **検算** — SageMath で厳密計算。仮説が否定された場合も必ず記録する。
3. **命題化** — 帰属（$\mathbb{N}/\mathbb{Q}/\Lambda/\overline{\mathbb{Q}}$）と $\mathbb{R}$ 脱出点を明示した statement にする。
4. **記述と形式化** — 構造化テキストへ移し、[証明の書き方.md](証明の書き方.md) の四層を適用する。

各段で**どこまで進んだかを明示する**（「検算まで。Lean 未着手」）。
黙って未検証のまま「証明した」と書かない。
