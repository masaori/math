# 全研究の監督契約

研究を進める定期起動とは独立に、六研究の方向を評価する。
対象の正本は [研究一覧](../../scripts/research-supervision/projects.ts)。記録は各研究の
`docs/tasks/supervision-log.jsonl` に追記する。停止中の研究も省略しない。
セルオートマトン専用だった契約・受理規則をここへ共通化した。

## 四つの判定

### 最終ゴールとの照合

各研究のREADMEの最終ゴールと、前回評価以降の実成果を読み比べ、`整合` または `逸脱` と根拠を書く。
セルオートマトンはマニフェストも読む。本文と検算に変更がなく、検査基盤の改修・再実行だけなら、
新しい数学的知識へ近づいたとは書かない。複素行列版では可読性が研究ゴールなので、実際に読める
依存順や説明の改善が本文に現れたかを評価する。処理成功・公開成功を研究の前進に置き換えない。
停止中の現状がゴールに未到達であることと、停止命令に従うことは両立する。

### 段取りの妥当性

判定は `妥当` または `要変更`。完了条件が有限検査へ落ちるか、依存が逆・不要になっていないか、
現在地と次の対象が最終ゴールへ接続するかを読む。段取りは専用ファイルに限らない。
本文の段階表、READMEの進める順序、runbookの上位ゴール、依存関係表と状態台帳を探して読む。
所在を `確認` / `部分的` / `なし` / `未確認` とし、読んだ資料の対象参照と不足を記録する。
未読を不在にしない。有限の初回範囲と研究全体の射程を混同しない。

### 証明済み事項から得たインサイト

実際に本文を読み、証明から次の探索方向を変えうる何が分かったかを書く。定理の再述で済ませない。
新しいインサイトが無ければ無いと書く。有限検算で得た反例・候補は一般証明の帰結と区別する。
既存台帳や過去の監督の判断は一次情報の所在を探す手掛かりであり、数学的根拠の代わりにしない。

### 段取りの変更

権限内の方向修正は今回実施し、差分と実在する根拠を残す。変更しない場合も理由を書く。
**ゴールを縮めない。** 証明できないから条件を弱める、射程から除く変更は禁止する。
新しい数学的主張・証明を進める操作、研究の再開、研究runbookの停止条件の上書きは行わない。
READMEの目的と明示停止を維持した段取り修正は、正本が本文・runbook・stateでも実施する。
人間判断が必要なら候補と根拠を記録し、他の研究の監督を続ける。
段取りを修正した場合は、その段取りの既存のプログラミングによる検証を通す。
監督記録だけを変更した回は、変更していない数学本文のLean・SageMath全体検査を繰り返さない。
監督プロセスへは `LEAN_NUM_THREADS=1` を渡す。初回実装時の同時ビルドが他repoの定期処理を
遅延させた実測を受け、必要なLean検査が生じても並列実行を広げない。

## 進捗を件数で測らない

証明件数・ブロック数・検査件数・ページ数は研究の進捗ではない。
各反復は、対象・仮説・反例・不変量・採否・インサイト・次の探索への接続を持つ。
採否は `採用` / `棄却` / `保留`。棄却には具体的反例が必須。反例・不変量が無い場合は空文字。
対象は本文にあるラベル、またはプロジェクト内の通常ファイルを指す。
ディレクトリ、存在しないラベル、プロジェクト外へ出るパスを受理しない。
共通の受理規則は [supervision-log-rules.ts](../../scripts/research-supervision/supervision-log-rules.ts)。

## 実行と研究を分ける記録

新規記録は `schemaVersion: 2`、研究名、今回の実行識別子、実施時刻、読んだ節と成果コミットを持つ。
上の四項目に加え、次を必須とする。

- `実行状態`: 観測時刻、起動の有無、直近の成否、実測証拠を保存したプロジェクト内パスと説明。
  起動の実体はlaunchctl list/printとplistの読取で今回観測する。読めなければ `未確認` とし、過去情報で埋めない。
  実ログは読み取り、そのパス・抽出行・観測時刻を保存する。ログ出力と研究内容の意味を分離する。
- `研究上の前進`: `前進` / `前進なし` / `未判定` と、実成果を読んだ根拠。
- `段取りの所在`: 本文も含む調査の結果と読んだ資料。ファイル名による判定は禁止する。
- `停止条件`: `人間指示の記録` / `運用文` / `なし` と根拠、必要な判断。
  人間の直接指示を読んでいない場合はその限界を書く。runbookの文章を本人の発言に格上げしない。
- `次の対象`: 実在する対象参照、次に問う具体的内容、READMEからの導出根拠。
  `研究再開の許可` は必ず `false`。候補の記述は停止解除ではない。
- `LLMによる検証` と `プログラミングによる検証`: それぞれ読解の範囲と実行結果を明記する。
  受理規則に通ることは、内容が数学的に意味を持つことを証明しない。

以前のセルオートマトン記録は変更せず残す。旧形式は履歴だけに許し、最新評価は全研究で新形式を要する。

## 一回の実行

既存起動口と監督専用worktreeを維持し、共通tickへ接続する。
一回で六研究を評価する。初回は同じ資料の観測区間を共有し、対象の一部だけの評価を成功としない。
所要時間は開始・終了の実測値をログへ残す。既存セルオートマトン単独の約五分という観測から
六研究の時間を推計しない。初回の六研究実行後の実測で分割・頻度変更の必要性を判断する。
定期起動の頻度は既存の六時間ごとを維持し、変更はtick窓口へ依頼する。

1. remote defaultを問い合わせてfetchし、監督専用worktreeへ取り込む。共有作業ツリーは編集しない。
2. 全研究のREADME、runbook、state、MEMORY、直前の監督記録と対応する実成果を読む。
3. 四項目と上の実行・権限の分離を評価し、各研究に今回の一行を追記する。
4. 下のプログラミングによる検証を通し、各MEMORYと既存の横断ゴール台帳を更新する。
5. 成果をcommitしてremote defaultへ反映し、fetch後のancestryを確認する。

```sh
structured-latex/node_modules/.bin/tsc -p scripts/research-supervision/tsconfig.json
node scripts/research-supervision/verify.ts --all
node scripts/research-supervision/verify-supervision-log-test.ts
node scripts/research-supervision/verify-test.ts
python3 scripts/test-research-tick-models.py
bash cellular-automata-statistical-mechanics/scripts/verify-cellular-automata-supervisor-tick.sh
```

共通tickは六研究それぞれの今回の追記、既存履歴の保存、remote defaultでの同一記録とancestry、
未コミット変更の不在まで判定して初めて正常終了とする。過去の有効な記録だけでは成功しない。
固定モデルは `gpt-6-astra`、reasoning `medium`、アカウントは正規起動口が起動前に一度選んで渡す `CODEX_HOME`。未設定・空なら起動前に失敗する。
利用上限・認証失敗を別モデル・別アカウントで回避しない。復旧は正規のtick窓口へ依頼する。
停止中研究の定期起動をロードしない。bootstrap/bootout/kickstart・plist編集は窓口の担当とし、
list/print・plist・実ログは読み取る。新規公開・通常完了のSlack通知は行わない。

未完の回は、モデル起動前に保存した実行識別子と開始コミットを次回へ保持する。未コミット・
未push成果があっても同じ回を完成させ、各研究の今回評価を重複追記しない。今回の追記と包含が
通ってから記録を解除する。不正な復旧記録・由来不明の変更は捨てず、エラーとして停止する。

起動口は `~/.local/bin/cellular-automata-supervision-launcher.sh`、本体は
`scripts/research-supervision/supervisor-tick.sh`、ログは
`~/Library/Logs/cellular-automata-research-supervision/supervision.log`。
既存のセルオートマトン側のスクリプトは互換入口として共通実装だけを呼ぶ。
