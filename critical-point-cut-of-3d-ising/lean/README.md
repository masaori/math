# Lean 形式検証（具体版と必要十分版）

規約の正本は [docs/context/証明の書き方.md](../../docs/context/証明の書き方.md) の
「四層の検証」である。ここにはこのプロジェクト固有の運用だけを書く。

## 2 つの版を置く

| 版 | 置き場所 | 何を保証するか |
| --- | --- | --- |
| 具体版 | `Ising3DCut/<章名>/` | **人手証明そのものが正しい**（人手証明と 1 対 1 に対応する） |
| 必要十分版 | `Ising3DCut/NecSuf/<章名>/` | **何が本質的か**。具体版が過剰な構造を要求していないかの検査 |

- **具体版は抽象度を人手証明と同じに固定する。** 人手証明のどのステップがどの補題かをコメントで対応づける。
  **人手証明の計算を mathlib の一般論へ委ねない**（委ねた時点で 1 対 1 対応の要件違反）。
- **必要十分版は証明手順を具体版と同じに保つ。** 別の論法へ差し替えたものは認めない。
  仮定は「具体版の証明が実際に使っている性質」だけにする。削れなかった仮定は
  **なぜ必要かをコメントに書く**（これが検査の本体）。
  **mathlib の高抽象度の既製定理へ丸投げしない。** 一行で終わる宣言や別名定義は認めない。
- **具体版が必要十分版の特殊化として得られること**を、導出の補題として明示する。
- 必要十分版は Lean の中だけに置く。人手証明にも参照用ノートにも持ち込まない。

## このプロジェクト固有の注意（立場）

本文の立場は「許される非可算への脱出は箱の大きさの極限だけ」である
（[README](../README.md)）。Lean 側でも次を守る。

- **本文に対応する定理は、$\mathbb{R}$ を使わずに述べる。** 有限集合の数え上げは `Finset` と `Nat`、
  有理数は `Rat`（mathlib の `ℚ`）で書く。`Real` を import しない。
- mathlib の実解析・測度論・確率論の一般論を持ち込まない。上の「丸投げ禁止」と同じ規律である。
- 箱の大きさの極限を扱う定理を書く段になったら、そこで初めて $\mathbb{R}$ が要るかを検討し、
  **本文側で脱出を宣言してから** Lean 側へ持ち込む。順序を逆にしない。

## 検査

```sh
cd critical-point-cut-of-3d-ising/lean
lake build
bash scripts/check-no-sorry.sh
```

`scripts/check-no-sorry.sh` は次の 3 つを見る。

1. すべての `.lean` が入口 `Ising3DCut.lean` から import されていること
   （import 漏れはビルドも検査もされない。2 次元側で実害があった）。
2. ソース中に `sorry` / `admit` が無いこと。
3. **登録した定理**が `sorryAx` に依存していないこと。
   **定理を増やしたらスクリプトの `targets` 配列へ必ず追加する**（追加漏れは検査の穴になる）。

## 依存（mathlib）

`lean-toolchain` と `lakefile.toml` の版は 2 次元側（`Ising2DLambda`）と同じ `v4.32.1` に揃えてある。
自動ループの tick は、`lake-manifest.json` が一致していれば 2 次元側の `.lake/packages` を
clone copy（copy-on-write）で持ち込む。実複製もダウンロードもしないためである。
版を上げるときは 2 次元側と同時に上げる（揃えておく理由がこれである）。
