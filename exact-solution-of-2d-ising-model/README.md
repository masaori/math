# 2次元 Ising 模型の厳密解 — ゴール設定と記述方針

**このプロジェクトで作業する前に、必ずこの文書を読むこと。**
証明を書く・直す・形式化する・レビューするすべての判断が、ここに書かれたゴールに従う。

---

## 1. ゴール

**丁寧に1つずつ積み重ねて読めば、高校生でも理解できる形で、2次元 Ising 模型の厳密解を証明する。**

これは「厳密であること」と同格の要求である。厳密だが読めない証明は、このプロジェクトでは失敗とみなす。

### 何を避けたいのか

**高い抽象度の道具立てを持ち込んだせいで、その一般論を理解しないと証明を厳密に追えなくなり、
本筋と関係ないところで頭のリソースを取られて挫折する**——これを避けたい。

典型例がリー群・リー環である。「指数関数の共役」を扱うのにリー理論を持ち出すと、読者は
リー群の定義・随伴表現・その一般論を先に理解しなければならなくなる。しかしその一般論は
Ising 模型の本筋とは関係がない。

### 理想の形

**頭からお尻まで、複素数とその行列の計算だけで完結する。**

例外は最後の「実数への脱出」（連続極限・積分）のみ。ここだけは実数解析が要るので、
**どこで脱出したかを明示する**。

## 2. 使ってよい道具・使わない道具

| | 道具 | 扱い |
| --- | --- | --- |
| ○ | 複素数とその四則演算 | 土台。定義に必要な演算（和・積）だけを入れる |
| ○ | 複素数を成分とする行列とその積 | 土台 |
| ○ | 有限和・有限積 | 添字計算として書き下す |
| ○ | 集合の初等的な扱い（同値関係・商集合を含む） | 偏角の分岐を厳密に扱うのに必要。**現行のまま維持する** |
| ○ | 極限・級数（指数関数の定義に必要な範囲） | ノルムと収束を明示的に定義したうえで使う |
| △ | 実数解析（積分・連続極限） | **最後の熱力学極限でのみ**。脱出箇所を明示する |
| ✗ | リー群・リー環 | 使わない。指数関数の共役は**級数展開だけ**で示す |
| ✗ | 抽象テンソル積の一般論 | 使わない。**具体的なクロネッカー積**を専用記号で定義して使う |
| ✗ | 環・体などの一般論に持ち上げた証明 | 主張は複素行列について具体的に述べる（下記 4 節） |

### テンソル積について（重要）

`M` 個の 2×2 行列のテンソル積は、**具体的な 2^M × 2^M の複素行列（クロネッカー積）として
専用の記号で定義する**。抽象的なテンソル積の一般論（基底のテンソル積が基底、など）は本文に出さない。

抽象的な見方は参照用ノートに書いてよいが、その際は
**「ゴールに照らして本文には採用しなかった」旨を明記する**。

## 3. 新しい道具を導入するときの判断基準

証明の途中で新しい概念・記号・定理が必要になったとき、次を順に問う。

1. **これを理解しないと先へ進めないか。** そうでないなら入れない。
2. **本筋か、脇道か。** 脇道の一般論なら、具体的な形に落として本文に書く。
3. **より初等的な書き方で済むか。** 済むならそちらを採る（記述が長くなっても構わない）。
4. **入れる場合、その定義は本文にあるか。** 「暗黙に使われている未定義の概念」を残さない。

過去の失敗例: 行列ノルムを定義しないまま複数の章で使っていた。指数関数の収束を論じるには
ノルムが要るので、**定義を本文に追加**して解消した。逆に「極座標表現が体をなす」という主張は
**どこからも使われておらず**、加法を定義しないと意味も確定しないので**削除**した。

## 4. 一般化について — 人手証明は具体、Lean は具体と抽象の両方

### 人手証明（本文）は具体に固定する

**主張は複素行列について具体的に述べる。** 一般の環・体へ持ち上げない。

理由: 「任意の環で成り立つ」と書くと、読者は環の定義と「複素行列が環をなすこと」の証明を
先に要求される。証明そのものが分配法則と結合法則しか使っていなくても、**述べ方が抽象的**なら
読者の負担は発生する。

### Lean は同じ主張に対して2つの証明を置く

具体的な対象だけで書くことには弊害もある。**その対象のどの構造が証明にとって本質的なのかが
見えなくなる**。そこで機械的証明の側では、同じ主張について次の2つを用意する。

| | 何を書くか | 何のためか |
| --- | --- | --- |
| **具体版** | 人手証明と**同じ抽象度**（複素行列）で、**1対1に対応する**厳密証明 | **人手証明の正当性を保証する。** 対応が直接的なので、どのステップがどれに当たるかを追える |
| **抽象版** | **不要な構造を取り払い、証明に必要な概念だけを残した**抽象度での証明 | **何が本質的かを明らかにする。** 同時に、具体版が不必要に複雑な構造を要求していないかの**検査**になる |

**抽象版は説明のための道具であり、検査でもある。** 例えば「交換子と反交換子の恒等式」を
任意の環で証明できるなら、その主張には**行列であることも複素数であることも本質的でない**
（分配法則と結合法則だけで足りる）と分かる。逆に、抽象版を書こうとして必要以上の構造を
仮定しないと通らないなら、具体版の証明が余計な性質に依存している疑いがある。

### 規約

- 両版に**同じ人手証明のラベル**をコメントで明記し、対応を追えるようにする。
- **抽象版から具体版が特殊化で得られる場合は、その導出を明示的に書く**
  （具体版を抽象版の系として得る形でよい。ただし人手証明と1対1に対応する形の主張は必ず立てる）。
- **抽象版は Lean の中だけに置く。** 人手証明の本文にも参照用ノートにも持ち込まない
  （本文の抽象度を上げないため）。抽象版から得られた知見（「この主張に行列であることは
  効いていない」等）を book/論文で述べたい場合は、**その知見を具体的な言葉で書き直す**。

## 5. 「なぜこの計算を思いついたのか」を説明する材料（読み物）

厳密証明に含められないが、**なぜこの計算プロセスに至ったのかを説明するのに本質的な数学的構造**がある。
これらは**厳密証明とは別に、読み物として整理する性質のもの**であり、
**参照用ノートに残す。厳密な形でなくてよい。**

代表例が**クリフォード代数**である。証明に現れる演算子たちが満たす関係式は、そのまま
クリフォード代数の定義関係式であり、「なぜ共役が有限次元の線型変換に化けるのか」
「なぜ 2×2 行列の対角化だけで済むのか」「なぜ定数倍を除いてしか決まらないのか」という
**証明全体の骨格の理由**を与える。しかしクリフォード代数はテンソル代数の商代数として定義されるので、
[2 節](#2-使ってよい道具使わない道具)の基準からは本文に持ち込めない。

この種の材料の扱い:

- **参照用ノートに置く**（`structured-latex/notes/`）。厳密である必要はない。
- **本文の証明はこれに依存してはならない。** 本文は具体的な計算だけで自足していること。
- 出版物の解説パート（証明以外の部分）を書くときの素材として使う。
- ノートには「**厳密証明には含めない。理由は〜**」を明記する。

## 6. 採用しなかった経路の扱い

検討したが採用しなかった証明経路・道具立ては、**捨てずに参照用ノート（`structured-latex/notes/`）へ移す**。
その際、**「ゴールに照らして本文には採用しなかった」ことと、その理由を明記する**。

理由: 後から「なぜこの道を選ばなかったのか」を再検討できるようにするため。ただし
**最終成果物（論文・書籍）には載らない**（ノートは構造上、本文とは別に管理されている）。

現在ノートに退避してある主な例:
- リー群・リー環による「指数関数の共役」の経路（級数展開の経路を採用）
- 抽象テンソル積による見方（具体的なクロネッカー積を採用）

## 7. 構成と検証

構成・命名規則・検証コマンドはリポジトリ直下の [CLAUDE.md](../CLAUDE.md) を参照。要点だけ再掲する。

- **証明の正本**は `structured-latex/content/`。ここだけから最終成果物を生成する。
- **参照用ノート**は `structured-latex/notes/`。出版物には載らない。
- `_old/typst/` は旧 Typst 版の温存アーカイブ。**更新しない**。
- 変更したら検証をすべて通す（`validate-content` / `verify-no-lost-proofs` /
  `verify-check-linkage` / Lean の `lake build` と `check-no-sorry.sh`）。
