## ゴール（2026-08-14 に確定）

**最初のゴール設定は「可算コアの同定」である。**
すなわち、有限の立方格子について厳密に決まる可算データの上で、
**極限で効く部分と極限で潰れる部分を分離する。**

正本は
[docs/discussion/3次元Isingを可算側で書く/可算コアの同定とは何か.md](../docs/discussion/3次元Isingを可算側で書く/可算コアの同定とは何か.md)
である。要点だけ再掲する。

- 「有限系の可算データが全部を決めている」は定義から従うので**主張として立てない**。
  内容があるのは逆向き、**潰れる情報の同定**である。
- **帰無モデルを先に確定させる。** 二部性からの回文性 $\Omega_L(m)=\Omega_L(\#E_L-m)$、
  値と台の恒等式、そこから従う Galois 群の超八面体上限。**これを超える構造だけが内容になる。**
- **族は境界条件で添字づける。** 自由境界・偶数周期・外側を固定は別の族である。混ぜて比べない。
- **単変数の分配多項式だけでは相関を復元できない。** 多変数の分配多項式と箱の包含に伴う写像を含めて扱う。
- 極限量に効くかどうかを問う段で、初めて**箱の大きさの極限**（許される唯一の脱出）を宣言する。

**探索フェーズである。** 否定判定（判定手続きつき）も上記の正本に書いてある。
判定に当たったらゴール設定を降り、方針文書の候補一覧の次へ移る。

## 立場（このプロジェクトの根幹。姉妹プロジェクトより強い）

**明示的に宣言した脱出箇所以外では、$\mathbb{R}/\mathbb{C}$ を正当化されたものとして使わない。
そこに属する数のようなものを、定義・命題・証明の論理に一切登場させない。**

**許される非可算への脱出は、有限格子の量の列について箱の大きさを大きくする極限だけである。**

| | 道具 | 扱い |
| --- | --- | --- |
| ○ | 有限集合の数え上げ、有限和・有限積 | 土台。$\mathbb{N}$ |
| ○ | 整係数多項式環 $\mathbb{Z}[x]$、有理関数体 $\mathbb{Q}(x)$、有理数の不等式 | 土台 |
| ○ | 素因数分解と対数順序群 $\Lambda$、代数的数 $\overline{\mathbb{Q}}$ | 可算な拡大 |
| △ | 箱の大きさの極限 | **唯一の許される脱出。** 宣言して 1 回だけ取る |
| ✗ | 上限・下限（完備性）、積分、微分、無限和・級数 | 箱の大きさの極限ではない |
| ✗ | 指数関数・実対数、$x=e^{-2\beta J}$ の代入、逆温度の記号 | 同上 |
| ✗ | 乱流（random current）表現 | 重みに指数と無限和を含む |
| ✗ | 相・臨界温度・自発磁化などの無限体積の語を主張に使うこと | 極限を取る主張を別に立てるまで使わない |

$\mathbb{R}$ 側の定理は**辞書**として別に書く。動機づけと比較のために書き、
本文の命題の前提にも根拠にもしない。**$\mathbb{R}$ 側の定理から含意を借りない。**

## 格子の取り方（2 次元側と違う理由。ここを取り違えないこと）

**頂点集合は $\mathbb{Z}^3$ の有限な箱とし、その外側を $+1$ に固定する。
トーラス $(\mathbb{Z}/L\mathbb{Z})^3$ は使わない。**

理由は目的の違いである。2 次元側（`exact-solution-of-2d-ising-model-lambda`）が周期境界を取るのは、
分配多項式を転送行列の跡 $\operatorname{Tr}T^L$ として書き、その固有値と Fisher 零点を扱うためである。
周期性がなければ跡にならない。

このプロジェクトは転送行列も零点も使わない。使うのは**両側の証拠**であり、どちらも
「無限格子の有限部分集合についての主張」である。

- 低温側（Peierls 型）は「原点を箱の外から分離する」ことが議論の中身である。
  **トーラスには外が無いので、分離集合という概念そのものが書けない。**
  箱の外側を $+1$ に固定できることが必要である。
- 高温側の証拠も、$\mathbb{Z}^3$ の有限部分集合とその外へ出る辺について定義される。

**辺の集合は番号の集合とし、格子の形は端点写像だけが担う**（2 次元側と同じ規約。
辺の集合の定義に頂点集合を混ぜない）。数え上げの議論は「番号の集合の部分集合を数える」形になるので、
辺を頂点の 2 元集合として定義すると、数え上げの途中に頂点の構造が暗黙に混ざる。
**現状の本文はこの規約を満たしている。** 辺を始点と方向の組からなる有限集合として定義し、
格子の形は二つの端点写像だけが担う形へ書き直してある。

## 記述の規則

- **正本は構造化テキスト**（`structured-latex/content/`）。Typst では書かない。
- **一ステップ一定理**。式変形を省略せず、根拠を行末に $(\because\ \dots)$ で書く。
  本文で示した定義・主張の適用には `\blkref{<ラベル>}` でラベル参照を付ける。
- **記号の濫用を排除する。** 1 記号 1 意味。多項式とその値を区別する。
  同一視を「みなす」で済ませず、写像に名前を付ける。
- **住処 `habitat` を宣言する**（型と実行時検査で強制される）。
  非可算を宣言したら `realEscape` が必須。可算なら書けない。
- **未証明を未証明と書く。** 証明が書けていない主張は `todo` を残し、
  それに依存する主張には依存していることを明記する。
- 規則の正本は [docs/context/証明の書き方.md](../docs/context/証明の書き方.md) である。

### 章の到達点だけに主定理の印を付ける

主張・定理のブロックは `standing: "mainTheorem"` を宣言できる（入力言語の正本は
リポジトリ直下の [structured-latex](../structured-latex/README.md)）。**宣言が無ければサブ定理**
として扱われるので、印を付けるのは各章の到達点にあたるものだけにする。
判断に迷うものはサブ定理のままにする（あとから増やせる。減らすほうが難しい）。
定義・注意・ノートには宣言できない（型と実行時検査で落ちる）。

印は HTML の読み方に効く。各章の冒頭にその章の主定理が列挙され、サブ定理のブロックは
題名だけを見せて既定で閉じる。LaTeX / PDF の出力は印の有無で変わらない。

## 四層の検証

| 層 | 何をするか | 置き場所 |
| --- | --- | --- |
| 記述 | 一ステップ一定理・根拠の明示・住処の宣言で人手証明を書く | `structured-latex/content/` |
| SageMath 検証 | 式変形と数え上げを**一行ずつ**厳密に確かめる（`ZZ`/`QQ`） | `sagemath/check/<対象名>/` |
| Lean 具体版 | 人手証明と **1 対 1 に対応する**証明 | `lean/Ising3DCut/` |
| Lean 必要十分版 | 同じ手順のまま抽象度だけ必要十分まで上げる | `lean/Ising3DCut/NecSuf/` |

**四層すべてを満たしたときだけ「完了」と書く**（2 次元側と同じ運用）。
満たせない段階では、どこまで済んだかを必ず明示する（「記述と SageMath まで。Lean 未着手」）。
Lean 側の規約は [lean/README.md](lean/README.md)、SageMath 側は [sagemath/README.md](sagemath/README.md)。

## 構成と検証コマンド

```text
countable-core-of-3d-ising/
├── README.md                  # このファイル（ゴールと立場）
├── MEMORY.md                  # 引き継ぎメモ
├── structured-latex/          # 証明の正本（構造化テキスト）
├── sagemath/                  # 厳密計算による裏取り（ZZ/QQ のみ。浮動小数点は使わない）
├── lean/                      # 形式検証（具体版 Ising3DCut / 必要十分版 Ising3DCut/NecSuf）
├── docs/tasks/                # 自動ループの手順書と状態台帳
├── scripts/                   # 自動ループの起動スクリプト
└── logs/                      # 実行ログ（git 管理外）
```

```sh
(cd structured-latex && npm run gen)      # ラベル・集約モジュールの再生成
(cd structured-latex && npm run check)    # 生成物の鮮度 → 型検査 → 実行時検証 → ノート非混入
(cd structured-latex && npm run build:pdf) # PDF を作る（tectonic が必要）
node sagemath/tools/verify-check-linkage.ts # 検証 ↔ 証明の対応
(cd lean && lake build && bash scripts/check-no-sorry.sh)  # Lean（import 漏れ・sorry 非依存）
```

初回のみ `(cd structured-latex && pnpm install)`（Node 22.18 以降）。
