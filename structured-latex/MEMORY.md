引き継ぎメモ。次回やること・未解決問題・完了済み作業を書く。

## 次回やること

1. **M3（レンダリングコアと LaTeX / PDF 出力）**へ。
   `resolve` の出力から `.tex` を組み、tectonic で PDF まで通す。
   数式が LaTeX ∩ KaTeX の共通部分集合であることの機械検査（論点 D-1）もここで実装する。
   いま各プロジェクトの `tools/build-latex.ts` が独立に持っている変換規則を、システム側の
   出力器へ寄せるのが目的（同じ規則が 2 度書かれている状態は F9 と同型）。
   出力器を置く先はシステム内であり、**その置き方の先例は `live-preview/`（Web 出力器）が既にある**
   — ドメインモデルを使う側としてシステム内に載り、入力言語も解決も自前で持たない。
   LaTeX 出力器も同じ形にする。KaTeX 側の描画実績は `live-preview/` にあるので、
   D-1 の共通部分集合の検査はそこを一次情報として設計できる。
2. 移行時に各プロジェクトから上がったシステム側の不足（下記「未解決問題」）を、
   実例が 2 件以上そろった段で入れる。

## 未解決問題

- **移行時に各プロジェクトから上がったシステム側の不足**（いずれも回避策があり、移行は完了している）:
  - `HeadingBlock` がプロジェクト固有メタデータ `M` を受け取らない。見出し固有のメタデータを持つ
    プロジェクトはそのままでは移行できない（Ising は情報が復元可能だったので落とせた）。
  - 「見出しにメタデータを書くと型で落ちる」を利用者側が `never` の交差で書いている
    （integrable-lattice）。ファクトリが合成すれば各利用者の細工が消える。
  - `Origin.ordinal` が必須。ノートは通し番号を持たないのが自然。
  - `Origin.ordinal` の「正の整数」制約が型に無い（実行時検査のみ）。移行前の Ising は型で落としていた。
- **資産（画像ファイル）の受け入れと配信が未設計。** 正本は `assetKey` だけを持ち、実体への解決は
  ターゲットごとの資産解決器が担う、というところまで決めた（domain-model.md §7.5）。
  実際の受け入れ経路とストレージは M5 / M7 で決める。

## 完了済み

- **ローカライズを第一級のドメイン概念として実装**（2026-08-01）。
  - 文書・ブロック ID・ラベル・数式・参照先・画像資産キーはロケール中立、題名・本文・参照表示・
    引用注記・画像代替文はロケール固有として分離した。`LocalizedRevisionSnapshot` は原文ロケール、
    利用可能ロケール、翻訳元ロケールと翻訳元版を保持する。
  - 原文の存在、正準 BCP 47 表記、ロケール重複、翻訳系の循環、翻訳元の版不一致、共有構造の
    ドリフトを実行時検査で拒否する。原文は日本語 1 ロケールへ自動適合するため、既存プロジェクトの
    入力形式を変更しない。
  - 局所化した解決器、ライブプレビュー／公開サイト API、`DocumentLocale`・`Translation` 実体、
    任意の `locales.config.ts` を読む生成器と負テストを追加した。翻訳本文は追加していない。
  - 設計判断、不変条件、利用例、移行方法は README と domain model 文書へ記録。システム本体および
    Ising・可解格子の既存単一ロケール検証を通した。

- **M1**: [docs/domain-model.md](./docs/domain-model.md)。境界づけられた文脈は 2 つ（`document` / `live-site`）。
