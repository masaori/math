# MEMORY（structured-latex）

引き継ぎメモ。次回やること・未解決問題・完了済み作業を書く。

## 次回やること

1. **M3（レンダリングコアと LaTeX / PDF 出力）**へ。
   `resolve` の出力から `.tex` を組み、tectonic で PDF まで通す。
   数式が LaTeX ∩ KaTeX の共通部分集合であることの機械検査（論点 D-1）もここで実装する。
   いま各プロジェクトの `tools/build-latex.ts` が独立に持っている変換規則を、システム側の
   出力器へ寄せるのが目的（同じ規則が 2 度書かれている状態は F9 と同型）。
   出力器を置く先はシステム内である。静的HTMLの既定UIは `renderers/html/` へ集約済みなので、
   LaTeX 出力器も同じくシステム側へ置く。KaTeX側の描画実績は各論文の
   `tools/build-html.ts` を一次情報として設計できる。
2. 移行時に各プロジェクトから上がったシステム側の不足（下記「未解決問題」）を、
   実例が 2 件以上そろった段で入れる。

## 未解決問題

- **移行時に各プロジェクトから上がったシステム側の不足**（いずれも回避策があり、移行は完了している）:
  - `HeadingBlock` がプロジェクト固有メタデータ `M` を受け取らない。見出し固有のメタデータを持つ
    プロジェクトはそのままでは移行できない（Ising は情報が復元可能だったので落とせた）。
  - 「見出しにメタデータを書くと型で落ちる」を利用者側が `never` の交差で書いている
    （integrable-lattice）。ファクトリが合成すれば各利用者の細工が消える。
  - `Origin.ordinal` が必須。ノートは通し番号を持たないのが自然。
  - `Origin.ordinal` の「正の整数」制約が型に無い（実行時検査のみ）。移行前の Ising は型で落としていた。
- **資産（画像ファイル）の受け入れと配信が未設計。** 正本は `assetKey` だけを持ち、実体への解決は
  ターゲットごとの資産解決器が担う、というところまで決めた（domain-model.md §7.5）。
  実際の受け入れ経路とストレージは M5 / M7 で決める。

## 完了済み

- **節・要素グループ・主要要素を第一級の入力構造として追加**（2026-08-22）。
  - `DocumentStructure → Section → ElementGroup` の木で章立て、所属、グループ内部の主従を明示する。
    グループの中心 `focus` は定理・主張・定義を受け入れ、節の `primary` 所属との組合せから
    主定理・主な主張・主な定義を導出する。既存の `standing` は平坦な文書の互換入力として残した。
  - `compileDocumentStructure` は既存のセグメント契約へ渡すブロック列と所属索引を同時に作り、
    複数所属、構造 ID 重複、節の深さ超過を Result で拒否する。外部入力の実行時検証も追加した。
  - HTML 既定UIに、明示された所属だけから主要要素を取得し、「主な定義」と「主定理・主張」を
    節冒頭へ分けて表示するレンダラーを追加した。
  - 巨大文書は章ごとの `defineSection` で型を確定できる。codegen は `Section[]` /
    `DocumentStructure` の default export を直接読み、実行時と型レベルの双方でブロック列へ平坦化するため、
    構造を正本にしても文書全体の ID・ラベル検査を維持する。

- **主定理 / サブ定理の区分を入力言語へ入れた**（2026-08-17）。
  - `theorem` / `claim` にだけ `standing: 'mainTheorem' | 'subTheorem'` を宣言できる。宣言が
    無ければサブ定理（`DEFAULT_THEOREM_STANDING`）。定義・注意・ノート・見出し・図表に書くと
    型検査（`standing?: never`）と実行時検証（種別ごとに割ったスキーマ。`passthrough` でも効く）で落ちる。
  - 身分は意味なので `ResolvedTheoremLike.standing` まで運び、プロジェクト固有メタデータ `meta`
    には入れない。翻訳では変えられない（`localized-revision.ts` が構造として照合する）。
  - HTML の既定UIは `renderers/html/theorem-standing.ts`。見出しの冒頭に主定理を列挙し、
    サブ定理を `details` / `summary` で既定折りたたみにする（JavaScript 非依存）。
    定義・注意は身分を持たないので折りたたまない。LaTeX / PDF の出力は変わらない。
  - 最初の利用者は `exact-solution-of-2d-ising-model-lambda`（各章の到達点 17 件へ印を付けた）。

- **ローカライズを第一級のドメイン概念として実装**（2026-08-01）。

    引用注記・画像代替文はロケール固有として分離した。`LocalizedRevisionSnapshot` は原文ロケール、
    利用可能ロケール、翻訳元ロケールと翻訳元版を保持する。
  - 原文の存在、正準 BCP 47 表記、ロケール重複、翻訳系の循環、翻訳元の版不一致、共有構造の
    ドリフトを実行時検査で拒否する。原文は日本語 1 ロケールへ自動適合するため、既存プロジェクトの
    入力形式を変更しない。
  - 局所化した解決器、ライブプレビュー／公開サイト API、`DocumentLocale`・`Translation` 実体、
