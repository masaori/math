## 論点 A: 書籍形式のコラムの出どころ → **A-3**

書籍形式は「段組やコラムを差し挟んだ読み物」（`README.md`）である。そのコラムの中身をどこから持つか。
`notes/` を使うのは自明に見えるが、**I5（ノートは出版物に載らない）と正面から衝突する**。

| 選択肢 | 帰結 |
|---|---|
| A-1: コラムを新しいブロック種別として正本に追加し、対象出力を宣言する | 正本が出力形式を知ることになり §7.1 が崩れる。§7.4 の判定 4（例外扱い）に該当し、追加のたびに全ターゲットの出力器が対応を迫られる |
| A-2: `notes/` を書籍形式でだけ本文へ昇格させる | I5 が「PDF/LaTeX では載らないが書籍では載る」という条件付きになる。ノートの書き方の基準（「正しさに必要ならそれは注記ではない」）が揺らぎ、著者が判断できなくなる |
| **A-3（採用）**: 書籍を「本体文書 + 解説文書」の 2 文書の合成として扱い、合成規則をレイアウトが持つ | I5 も §7.1 も保たれる。解説文書はそれ自体が構造化テキストなので、同じ検査（I1–I3）を受けられる。代わりに「文書の合成」という概念がモデルに増える |

採用理由: I5 と §7.1 という既に一次情報で確定している 2 つの原則を、いずれも壊さない唯一の案。

M2 での現れ方: `resolve` の `anchorPrefix`。ブロック id は文書内でしか一意でないので、
合成する側が文書ごとに異なる前置を与えないとアンカーが衝突する。

## 論点 B: Web テーマにおけるコンポーネント差し替えの許容範囲 → **B-2**

| 選択肢 | 帰結 |
|---|---|
| B-1: 宣言的設定のみ（差し替えを一切許さない） | エントロピー最小。ただし Web 固有の対話性（折りたたみ・ホバー展開）を利用者が足せず、要求のたびにレンダラー本体を直すことになる。「レンダラー本体を書き換えなくてよい」（`README.md`）に反しうる |
| **B-2（採用）**: 閉じた役割ユニオンに限って型付きコンポーネントを許す | 差し替え可能な箇所が型で列挙され、Props が解決済み文書の型で固定される。テーマが正本に触れられないことは型で保証される |
| B-3: 任意のレンダリング関数を許す | 表現力は最大だが、テーマが何をするか型で予測できない。エントロピー最小化と型安全絶対条件の両方に反する |

採用理由: 「レンダラー本体を書き換えなくてよい」を満たす**最小の**開き方であること。

## 論点 C: 公開サイトの公開範囲 → **C-2**

| 選択肢 | 帰結 |
|---|---|
| C-1: 完全公開 | 実装が最小。未完成原稿が公開される |
| **C-2（採用）**: 文書ごとに公開／限定を選べる。限定時は招待された閲覧者のみ | `Document` に可視性の属性が増え、`read` policy が OR になる。招待という関係が 1 つ増える |
| C-3: 常に限定公開 | 「Web で公開できるサイト」という要件を満たさなくなる |

採用理由: 要件が「Web 公開」と「執筆中のリアルタイム共有」の両方を挙げており、片方だけを選ぶと他方が満たせない。

副作用として、`DocumentInvitation` は owner subject への FK パスが 2 本になる。
認可戦略 §4.2 の「パスが一意でなければエラー」に該当するので、policy 側で経路を明示する
（domain-model.md §12）。

## 論点 D: 数式方言の縛り方 → **D-1**

| 選択肢 | 帰結 |
|---|---|
| **D-1（採用）**: 共通部分集合を機械検査し、外れたら生成を落とす | 「黙って消える」が起きない。著者は書ける記法が制限される |
| D-2: LaTeX を正とし、Web 側は描画できないものを画像化等で劣化させる | 著者の自由度は上がる。Web の数式が部分的に画像になり、検索・選択・拡大の対象から外れる |

採用理由: 先行 3 実装がすべて「KaTeX 向けの LaTeX 文字列」で運用済みであり、
945 件の相互参照を含む 173 ページの PDF が実際にこの前提で生成できている
（＝共通部分集合が実用上足りていることが実測で確認できる）。

## 論点 E: 複数人が同時に「更新」することを要件に含めるか → **E-1**

| 選択肢 | 帰結 |
|---|---|
| **E-1（採用）**: 単一の書き手を前提とする。ただし `baseRevision` による楽観ロックは型に残す | lost update は検出でき、拒否して書き手に伝えられる。衝突の**マージ**は作らない |
| E-2: 複数の書き手の同時更新を初期から支える | セグメント単位のマージ規則が要る。§9.8 の「キー単位の全置換」と衝突し、選択肢が増える |

採用理由: 要件に明示されているのは「複数人で見る」ことだけで、書き手の同時性は一次情報にない。

**その後、依頼者から将来要求としてゼミ形式の共同執筆（編集権の受け渡し）が示された。**
これは E-1 を差し戻すものではない。編集権によって編集が直列化されるため、
E-1 が「作らない」と決めたマージ規則は依然として不要である（domain-model.md §16.1）。
