# Lean 形式検証（具体版と必要十分版）

規約の正本は [docs/context/証明の書き方.md](../../docs/context/証明の書き方.md) の
「四層の検証」である。ここにはこのプロジェクト固有の運用だけを書く。

## 2 つの版を置く

| 版 | 置き場所 | 何を保証するか |
| --- | --- | --- |
| 具体版 | `CellularAutomata/<章名>.lean` | **人手証明そのものが正しい**（人手証明と 1 対 1 に対応する） |
| 必要十分版 | `CellularAutomata/NecSuf/<章名>.lean` | **何が本質的か**。具体版が過剰な構造を要求していないかの検査 |

- **具体版は抽象度を人手証明と同じに固定する。** 人手証明のどのブロックがどの宣言かを
  ファイル冒頭のコメントで対応づける。
  **人手証明の計算を mathlib の一般論へ委ねない**（委ねた時点で 1 対 1 対応の要件違反）。
  使ってよい mathlib の補題は、人手証明が根拠に挙げる初等的事実そのものに限る。
- **必要十分版は証明手順を具体版と同じに保つ。** 別の論法へ差し替えたものは認めない。
  仮定は「具体版の証明が実際に使っている性質」だけにする。削れなかった仮定は
  **なぜ必要かをコメントに書く**（これが検査の本体）。
  **mathlib の高抽象度の既製定理へ丸投げしない。** 一行で終わる宣言や別名定義は認めない。
- **具体版が必要十分版の特殊化として得られること**を、導出の補題として明示する。
- 必要十分版は Lean の中だけに置く。人手証明にも参照用ノートにも持ち込まない。

## このプロジェクト固有の注意（立場）

このプロジェクトは、有限舞台・有限状態集合・有限真理値表から内在的に生じる数学構造を
先に抽出する（[docs/マニフェスト.md](../docs/マニフェスト.md)）。Lean 側でも次を守る。

- **本文に対応する定理は、$\mathbb{R}$ を使わずに述べる。** 有限型・`Finset`・`Nat` で書き、
  `Real` を import しない。非可算な対象（無限舞台上の全配位空間など）を持ち込む段になったら、
  **本文側で脱出を宣言してから** Lean 側へ持ち込む。順序を逆にしない。
- 状態集合 $A=\{0,1\}$ は構造を入れない 2 元集合なので、`Bool` や `Fin 2` の既成の演算を
  流用せず、演算なしの帰納型として定義する（構造を入れるときは名前に付ける、という
  呼び名の規約の対応物）。

## 検査

```sh
cd cellular-automata-statistical-mechanics/lean
lake build
bash scripts/check-no-sorry.sh
```

`scripts/check-no-sorry.sh` は次の 3 つを見る。

1. すべての `.lean` が入口 `CellularAutomata.lean` から import されていること
   （import 漏れはビルドも検査もされない）。
2. ソース中に `sorry` / `admit` が無いこと。
3. **登録した定理**が `sorryAx` に依存していないこと。
   **定理を増やしたらスクリプトの `targets` 配列へ必ず追加する**（追加漏れは検査の穴になる）。

## 依存（mathlib）

`lean-toolchain` と `lakefile.toml` の版は既存プロジェクト（`Ising2DLambda`・`Ising3DCut`）と
同じ `v4.32.1` に揃えてある。自動ループの tick は、`lake-manifest.json` が一致していれば
既存プロジェクトの `.lake/packages` を clone copy（copy-on-write）で持ち込む。
実複製もダウンロードもしないためである。版を上げるときは全プロジェクト同時に上げる。
